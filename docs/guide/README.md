# 引导局（`docs/guide/`）

这里放**新手引导**里那几副「引导局」的数据：一副**真实牌局**的全部事实 + 用户座位每一步的引导词。
下游 `/learn` 读生成物 `apps/web/src/lib/guide/deals/<slug>.ts` 渲染教学桌面（ADR-0025）。

## 怎么产出一副

1. **拿到一份 db 副本**：把部署机上的 `sixty.db` 拷到 `data/guide-source.db`（gitignored）。
   本地三人真人开桌打的开发库同样可用；也可以用 `SIXTY_GUIDE_DB=<路径>` 指定别的位置。
2. **列候选**：`pnpm --filter web guide:extract`
   - 只会列出**三人均非机器人**（`users.is_bot` 全 0）且**已结算**的牌；
   - 常规路径每桌只取**最后一副**（`games.state` 只留当前这副）。历史副并非取不回来：
     `events` 表记着每副的叫牌 / 埋底 / 逐墩，`dealScored` 事件带完整结算摘要，
     按 `replayInputOf` 同一套数学同样能还原（第一批评审用的 19 副就是这么来的）；
   - 输出 `docs/guide/candidates/<桌码>-<副号>.json`（草稿：事实与动作齐备，其余待填），
     并在控制台打一行摘要（定约 / 打成打输 / 墩数 / 三家主牌张数 / 副前级别）。
3. **挑一副、挪进来**：把选中的那份挪成 `docs/guide/<slug>.json`（**挪、不是复制** ——
   同名同时出现在 `candidates/` 与正式目录会被测试拦下）。`candidates/` 不进仓库。
4. **补齐人和话**（见下表）：
   - `title`：这一副讲什么；
   - `aliases`：三个座位的代称（用户那一席必须写「你」）；**真实用户名不进仓库**，
     来源只记桌码 / 副号 / 日期；
   - `guides`：**用户座位的每一个动作都必须有一条引导词**（缺一条就会被校验挡下），
     可再给一条 `why` 当事实依据；
   - `notes`（可空）：对手动作的一句话解说；
   - `review`：复盘屏的开篇 / 逐墩要点 / 收尾。
5. **生成**：`pnpm --filter web guide` → 写 `guide/deals/<slug>.ts` 与 `index.ts`（提交进仓库）。
6. **校验**：`pnpm --filter web guide:check` 只校验不写。任何一条不过都**非零退出并列出全部问题**，
   绝不写半个文件。

## 校验到底查什么

| 层 | 查什么 |
| --- | --- |
| 结构 | 版本 / slug 与文件名一致 / 代称三名且用户那席是「你」/ 事实齐备 / 牌键存在且是**规范写法**（`C13`，不是 `CK`）/ 引导词与解说的下标都落在动作范围内 |
| 语义 | 用引擎从**显式手牌**重放整副：每一步必须合法、不许出现全 pass 重发；`expect`（结算存证）必须与现场重放逐项一致；`role` 与庄家座位一致；**用户座位每个动作都有引导词**、对手动作一条都不许有；复盘墩号不越界 |

生成物与现场重算的一致性由 `test/guide-generated.test.ts` 守着（手改生成物、或改完 JSON 忘了重跑
`guide`，CI 会红）；`scripts/build-guide.ts` 的 `--check` 是同一个判据的手动入口。

## 数据从哪来（为什么不是编排出来的）

引导局的生命力在「这真是三个真人打出来的」：叫牌的让与争、埋底的取舍、末轮的博弈都带着真实代价。
所以取材硬门槛是**三人均非机器人**，且**一副引导局必须是整副真实牌局**（客户端从显式手牌
`dealWith` 重放，见 ADR-0025）——不合成、不改打。找不到合适副的课程按大纲降级为「概念 + 测验讲透」，
在课程的步里写 `pending` 说明，不硬凑。
