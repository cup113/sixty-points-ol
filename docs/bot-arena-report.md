# 机器人参数竞技场报告（ADR-0017）

这一轮的产物是三样东西：**一份显式参数面**（`BotParams`，缺省即出厂行为）、**同伴概念**、
以及一个**同副牌配对竞技场**（`packages/bot/src/arena.ts` + `packages/bot/scripts/arena.ts`）。
这份报告是竞技场给出的全部读数与由此做出的取舍 —— 包括**被数据否掉的、以及否掉我上一轮判断的**那些。

复现方式（`pnpm arena -- …` 等价）：

```powershell
node packages/bot/scripts/arena.ts --mode deal --seeds 2000 --rotations 3 --ratio 1
node packages/bot/scripts/arena.ts --mode game --seeds 100  --rotations 3 --ratio 1
# 晋升之后要量「这轮到底改了多少」，得把历史值显式写成变体（`undefined` 已经是新默认了）：
node packages/bot/scripts/arena.ts --mode deal --seeds 2000 --seed0 9000 --ratio 1 --only legacy-baseline
```

原始 JSON 与逐 cell 报告在 `data/_analysis/arena/`（**已 gitignore**，不入库）。下面每个数字都由
`scripts/arena.ts` 直接写出，没有手抄。

## 1. 方法（为什么这些数字可以信）

| 设计 | 作用 | 被什么钉死 |
|---|---|---|
| 同一种子 = 同一副牌（`rngFactory` 只取决于种子） | 两侧拿到的牌完全一样 | `test/arena.test.ts`：只改打牌参数时合同与将牌逐字不变 |
| 座位轮换 3 圈取平均 | 抵消座位/角色偏差，1:2 与 2:1 因此可比 | `A/A` 恒为 0；**轮换取 2 时 A/A ≠ 0**（−0.006），CLI 已加告警 |
| 独立单位 = 种子 | 同种子的三圈是聚类的 | 先按种子取均值，再 bootstrap 区间 + 符号翻转置换检验 |
| `A/A` 标定细胞 | 证明估计量无偏、轮换没偷换牌 | 每批 2000 种子 × 2 配比，Δ 恒为 0、CI=[0,0] |
| 机制计数从 `(视图, 动作)` 流推出 | 证明开关**真的接线了**（不是「没生效所以没差别」） | `test/arena.test.ts` 的「开关接线」用例 |
| 空转守卫 | 变体参数若与当前基线逐字相同，显式标成**空转** | 晋升之后最容易踩的坑，我真踩过一次（§6） |

进 CI 的不变量在 `test/arena.test.ts`（等价、确定性、A/A 恒 0、严格配对、功效非空转、开关接线、默认值钉死），
以及 `test/policy.test.ts` 里**每个开关一个固定局面**的 7 条用例 —— 每条同时钉「默认怎么做」与
「拨动之后确实变了」。用注入法验过其中最容易写虚的那条：把「不抢同伴已得赢墩」短路掉，用例立刻红
（`认同伴：本墩已是本侧的，出最小的，把 ♠A 留住`），还原后 sha256 与注入前一致。

读数定义：
- **单副台**：每座位每副**升级数**（变体 − 基线）。级别按种子钉死（`rank = 2 + seed % 13`，覆盖 13 个级牌）。
- **整局台**：每座位**终局进度**（`13 × 轮数 + 档位`），打到引擎判定结束（2 人 ≥27 或 1 人 ≥40）。
- **谁先打完**：终局最高进度落在哪一侧，与**公平份额**并排读（1 变体 + 2 基线时是 33.3%）。
- MDE = `2.8·σ(D_s)/√N`，σ 取本 cell 的**种子均值**离散度。A/A 的 σ 恒为 0，所以 A/A 不给 MDE ——
  它在这一项上退化了，不能拿来标定噪声（这是我第一版写错的地方）。

## 2. 主结果

### 2.1 单副台：逐变体（2000 种子 × 3 轮换；两个配比各一遍）

| 变体 | 1 变体+2 基线 | 2 变体+1 基线 | 判定 |
|---|---|---|---|
| `bid-ladder-6`（竞叫阶梯原点 12→6） | **+0.2818** [0.2415, 0.3236] | **+0.2707** [0.2367, 0.3062] | 采纳 |
| `bid-both-6`（门槛 6 + 阶梯 6） | +0.2542 | +0.2678 | （等价，见 §3.1） |
| `bid-both-8` | +0.2240 | +0.2289 | — |
| `bid-both-10` | +0.1400 | +0.1268 | — |
| `partner-feed`（不抢同伴 + 喂分） | +0.0572 [0.0490, 0.0655] | +0.0580 [0.0500, 0.0660] | 采纳 |
| `feed-only`（只喂分） | +0.0478 | +0.0478 | 并入上面那一对 |
| `lead-aggressive`（领地余量 {2,5}→{1,2}） | +0.0372 | +0.0349 | 采纳 |
| `discard-loose`（垫牌分权重 30→0） | +0.0162 | +0.0130 | **不采纳**（见 §4） |

其余对照项同样为负：`ruff-never`(−0.0948/−0.1132)、`fight-big-only`(−0.1085/−0.2052)、
`lead-cautious`(−0.0160/−0.0147)、`bid-16`(−0.5282/−1.0725)；
`discard-greedy`（权重 30→90）是**恰好 0.0000** —— 权重 30 与 90 从不改变垫牌次序，这个字段只在降到 0 附近才有效。

### 2.2 整局台：逐变体（100 种子 × 3 轮换）

| cell | Δ每座位终局进度 | 谁先打完（份额 / 公平份额） |
|---|---|---|
| `bid-ladder-6` | **+14.29** [13.07, 15.49] | **73.8% / 33.3%** |
| 组合（阶梯+同伴+领地+垫牌） | **+16.21** [15.20, 17.22] | **82.1% / 33.3%** |
| `lead-aggressive` | +1.62 [0.77, 2.48] | 36.5% |
| `discard-loose` | +0.81 [0.04, 1.58] | 31.8% |
| `feed-only` | +0.43 [−0.28, 1.14] | 37.8% |
| `bid-open-6` | **−0.58 / −1.00** | — |
| `A/A` | 0 恒等 | 32.5%（公平 33.3%） |

「谁先打完」的 A/A 校验：1 变体 + 2 基线下 32.5%（公平 33.3%），2 变体 + 1 基线下 67.1%（公平 66.7%）。
两类配比都没有系统性偏向 —— 这是「73.8% 不是读数造出来的」的直接证据。

### 2.3 晋升之后：新默认对历史基线（**独立种子批次 9000 起**）

`undefined` 现在就是新默认，所以「历史基线」必须显式写成变体（`legacy-baseline`）。
表里 Δ = 变体 − 基线 = 历史基线 − 新默认，**取负号**才是「新默认领先多少」：

| 对比 | Δ（新默认 − 历史基线） | 谁先打完（新默认份额 / 公平份额） |
|---|---|---|
| 单副台，1 个新默认 : 2 个历史基线 | **+0.352** [0.307, 0.397] | — |
| 单副台，2 个新默认 : 1 个历史基线 | **+0.239** [0.205, 0.273] | — |
| 整局台，1 个新默认 : 2 个历史基线 | **+15.66** 进度 [14.53, 16.79] | **82.6%** / 33.3% |
| 整局台，2 个新默认 : 1 个历史基线 | **+9.00** 进度 [8.04, 9.94] | **91.2%** / 66.7% |

两条读数指向同一件事，也解释了为什么两个配比的数字不同：

- **一个孤立的新默认机器人能赢过两个历史基线机器人 82.6% 的对局**（公平份额 33.3%）；
- 两个新默认机器人同场时，它们**互相争**庄家位，于是「每个座位的份额」被摊薄（91.2% vs 公平 66.7%，
  但每座位进度差从 +15.66 降到 +9.00）。

这正是「1:2 与 2:1 都要跑」的理由：**争夺庄家位的收益取决于场上有多人同抢。**

### 2.4 独立复现（换一段没跑过的种子）

| cell | 原批次（1..100 / 1..2000） | 复现批次（5000 起） |
|---|---|---|
| `bid-ladder-6`（整局台） | +14.29 | **+13.07** |
| 组合（整局台） | +16.21 | **+15.59** |
| `lead-aggressive`（整局台） | +1.62 (p=0.0003) | +0.65 (p=0.156) |
| `feed-only`（整局台） | +0.43 (p=0.245) | +1.13 (p=0.010) |
| 组合（整局台，1:2，晋升后那一批 9000 起） | +16.21（4 项） | **+15.66**（3 项） |

**大效应稳，小效应在整局台的噪声里**（N=100 局时 MDE ≈ ±1.0~1.2 进度）。
所以第二梯队不是靠整局台定的，而是靠单副台 2000 种子（MDE ≈ ±0.008~0.02）定的：
**两个台子分工不同 —— 单副台分辨小效应，整局台回答「会不会赢」。**

## 3. 三条机制（这一轮最值钱的部分）

### 3.1 收益的大头是「庄家位」，不是「打得更好」

把 500 种子的组合拆开（`data/_analysis/decompose-probe.mjs`）：

| 情形 | 副数 | Δ（每座位每副升级数） |
|---|---|---|
| 变体做庄 | 765（51.0%） | **+1.59** |
| 基线做庄 | 735（49.0%） | **−1.02** |

同一副牌，「谁坐庄」几乎决定了升级归属 —— 升级表把主要级数给了庄家侧
（打成 1–5+ 级；闲家只在庄家打输时按 `ceil(差/10)` 升级）。这一条同时解释了一组看上去矛盾的读数：

- **`bidLadderBase` 降下来（愿意一路用最小步长把价加到 50/60 分）是巨大正收益**：抢到庄家位就值这个价；
- **`bidJump`（跳叫）是负的**：跳叫把同一件事做过头 —— 白抬及格线，买不到任何级数；
- **`bidBar`（开叫门槛）单独降下来在整局台是负的**（−0.58/−1.00）：没人叫过时你的牌是「随机偏弱」，
  拿这种牌做庄是亏的。**门槛 12 是对的，该改的是「抢别人叫品时愿意加到哪」。**

这是我的第一版实验**没拆出来**的：`willingPoints` 里开叫门槛与竞叫上限原本是同一个常量，
`bid-6` 那个 +0.25 是两件事的合成。把阶梯原点独立成字段（`bidLadderBase`）才看清：
**+0.28 里的 +0.27 来自竞叫上限，开叫门槛的贡献是 +0.005（整局台还是负的）。**

### 3.2 上一轮那个结论被推翻了：大王不该留

上一轮复盘（真实牌局的 case study）认为「拿到牌就出大王」是错的，举证 T5d3（底 25×2）与 T2d2（底 10×1）
两副都是庄家保底。竞技场说：**把大王留到末轮 = −0.096 级/座位/副**，两个配比各 6000 副，CI 不含 0。
机制计数也证明开关接了线（大王单张领出 7.43 vs 32.77 每 100 座位-副，×0.23）。

两个读数并不矛盾：那两副牌里闲家的末轮**本来就赢不了**（T5d3 末轮 x=2、闲家一张主牌不剩），
而台子量的是 6000 副的平均 —— 用大王抽主把对手的杀牌/护底资本抽掉，平均比留着它值钱。

**教训：个案研究只能用来提出假设，不能用来定策略。**上一轮给你的那段结论是错的，这份报告更正它。

### 3.3 同伴概念：价值在「喂分」，不在「不抢」

依据是引擎的结算公式：`finalScore` 只算**庄家**抓到的分与底牌，闲家抓到的分永不进入这个式子，
只起「不让庄家拿到」的作用。所以本墩归属已定时（我是第三家、当前赢家是同伴），把分垫给同伴
= 把分从庄家的账上拿掉。

| 开关 | 单副台 | 机制计数（每 100 座位-副） |
|---|---|---|
| `partnerAware` 单独 | +0.0038 [−0.0048, 0.0122]（**与 0 不可区分**） | 抢同伴的墩 21.1 → 9.5（×0.45） |
| `feedPartner` 单独 | +0.0478 | 送给同伴的分 16.6 → 28.5（×1.72） |
| 两个一起 | +0.0572 | 两者都动 |

也就是说：**「不抢同伴的墩」本身几乎不换钱**（它只改变手里留下什么），钱在「把分送到同伴账上」。
两个都进默认，是因为被量的是这一对，而且「不抢」让喂分规则自洽（否则你会一边把分喂给同伴、
一边又把那一墩抢回来）。但收益**不能**单独归因到「不抢」那一半。

组合细胞里还能看到一条副作用：`pointsToDeclarerPoints` 从 17397 降到 12145（×0.70）——
**喂分 + 更激进的领出合起来，真的让庄家少收了约 30% 的分**。分牌积极性这个方向是有真实作用的。

## 4. 采纳了什么，以及为什么

事前定的采纳门槛是四条：机制计数非零、CI 不含 0、Holm 校正后显著、**幅度 ≥ +0.1 级/座位**，
且整局台不同向为负。

| 字段 | 旧 → 新 | 幅度 | 证据强度 |
|---|---|---|---|
| `bidLadderBase` | 12 → 6 | **+0.282 / +0.271** | 极强：4 个单副台细胞 + 6 个整局台细胞，两个配比、两批种子 |
| `leadCaution` | {2,5} → {1,2} | +0.037 / +0.035 | 强：单副台两配比显著；整局台 +1.6/+0.9（复现批次 +0.65，噪声内） |
| `partnerAware` + `feedPartner` | false → true | +0.057 / +0.058 | 强（**这一对**）：单副台两配比 + 整局台；单独的 `partnerAware` 不可区分 |

**只有第一项过了幅度门槛**（+0.27，三倍余量）。后两项（+0.037、+0.057）没到 +0.1，仍然被采纳 ——
理由是它们各自在两个配比、2000 种子下都显著，机制计数证明开关真的接线，整局台同向为正，
而且都是「打得更对」这一类不会互相冲突的改动。**这是一次有意偏离事先门槛的决定**，所以写在这里：
将来若要收缩参数面，先砍的是这两项，不是阶梯。

**不采纳 `discardPointWeight: 0`。** 它四次单副台读数全为正（+0.0183 / +0.0153 / +0.0162 / +0.0130）、
整局台 +0.81，但：① 幅度只有 +0.016，**只有门槛的六分之一**；② 整局台的读数过不了 Holm；
③ **机制对不上** —— 它其实只改变「5/10 这类分牌与相邻低张谁先垫」的次序（`level×2` 项在不计分时反超），
而送给庄家的分几乎没变（0.98–0.99×），也就是说它**并没有做到「少送分」这件它看起来该做的事**。
读数为正、但做的事不是它看起来该做的事 —— 这一项不进默认，事先门槛就该在这时候起作用。

## 5. 晋升之后：出厂行为变了多少

同一个探针（120 局全默认、2825 副；另跑 24 局与 `fullgame.test.ts` 同规模）：

| 读数 | 历史基线 | 新默认 |
|---|---|---|
| 开叫率 | 53.8% | 53.9%（`bidBar` 没动，理应不变） |
| 全 pass 重发率 | 4.7% | 5.2% |
| 庄家打成率 | 81.4% | **64.1%** |
| 每副升级 庄 / 闲 | 2.22 / 0.63 | 1.71 / 1.36 |

定约更难打成（64% vs 81%）是必然的：愿意把价抬到 50/60 分，及格线就更高。
但升级归属整个翻了过来 —— 这正是 §3.1 那条机制的另一面。

**必须如实说的代价**：§2.3 那个 82.6% 是对**历史基线**的胜率，而代价落在陪练体感上 ——
新默认机器人抢庄比基线凶得多，这一点有直接的读数（`shipped-deal-ratio1/2.json` 的「庄家侧」表）：

| 桌型（单副台 6000 副） | 庄家位落在谁手里 |
|---|---|
| 1 个历史基线 + 2 个新默认 | 基线座位 **17.1%**、两个新默认座位合计 82.9%（公平份额是 33.3% / 66.7%） |
| 2 个历史基线 + 1 个新默认 | 每个基线座位 24.5%、新默认座位 **51.0%**（按座位算，新默认拿庄家的频率是基线的 **2.1 倍**） |

也就是说：**一个「基线那样温和」的座位夹在两个新默认机器人中间时，坐庄机会从 1/3 掉到约 1/6。**
这不是可以含糊过去的细节：想练叫牌就把 `bidLadderBase` 抬回 8~12 ——
它是实验里唯一一根「强度旋钮」，另外两项都不改变争庄的态势。

## 6. 没做到的、和不该过度解读的

- **样本是机器人自己**。前置的真实牌局复盘只覆盖 7 桌 16 副，而人类对手的打法与基线不同。
  「新默认强于历史基线」是**对基线**的结论，不等于对人类的胜率。
- **整局台的读数是「赢家通吃」的形状**：结束时输家的进度被冻在那一刻。所以 +15.66 不要读成
  「多打 15 级」，它读作「先到终点、且甩开这么远」；要看效应量级请用单副台那一列。
- **`A/A` 只证明估计量无偏**，它不能用来标定噪声（σ 恒为 0，MDE 这一项退化）。
- **晋升会静默地让旧cell 变成空转**：同一批变体在晋升之后重跑，7 个细胞里有 6 个的变体参数
  与新的 `undefined` 逐字相同，于是一律给出 Δ=0、p=1 —— 看上去像「没有效果」，其实是「没换配置」。
  CLI 现在会把这种细胞标成**空转**并告警，`legacy-baseline` 变体就是为这种场景准备的。
- **没做的方向**（想推进要单独立项）：防守方「穿同伴已证缺门」的协作领出、用同伴缺门诱导杀牌、
  叫牌阶段利用搭档信息，以及任何搜索/学习类方法（ADR-0015 明确不做）。
- **本节涉及的三份旧讲评（`docs/deals/*.json`）已随 ADR-0025 退役**：它们是作者自己打出来的记录，与机器人策略无关，
  作为历史结论保留；当时的结论「这条链路不 import `@sixty/bot`」对现在的 `pnpm guide:check` 同样成立
  （引导局校验只 import 引擎）。
- **机器重演（ADR-0016）是快照**：已落库的记录保持原样（那正是快照的语义），但同一副牌在参数变了之后
  重算会给出不同结果 —— 这是「策略是版本化输入」的直接后果，不是缺陷。

## 7. 后续：叫牌精细扫描（曲线，以及为什么默认没再动）

晋升之后有人问「叫牌积极性试过别的档位吗」。回看证据面：`bidLadderBase` 当时**只量过 6 与 12 两个点**
就把 6 提为默认，等于在一条没画过的曲线上取一个点当最优。于是补了 15 个变体，把五个维度分别扫开
（每点 2000 种子 × 3 轮换 × 两个配比，Holm 校正；基准 = **当时的出厂默认**，所以表里的 0 就是「与现值相同」）。

### 7.1 竞叫阶梯原点：单峰，峰值在 8 —— 我原来那个点偏保守

| 原点 | 1 变体+2 基线 | 2 变体+1 基线 | 竞叫/100 座位-副 | 变体做庄时打成率 |
|---|---|---|---|---|
| 0（最凶） | −0.121 | −0.095 | 137.5 | 53.8% |
| 2 | −0.084 | −0.077 | 131.4 | 56.2% |
| 3 | −0.088 | −0.076 | 129.6 | 56.7% |
| 4 | −0.044 | −0.034 | 121.1 | 59.9% |
| **6（当时默认）** | 0 | 0 | 113.9 | 65% |
| **8** | **+0.021** | **+0.030**（p=0.0067） | 87.6 | 73.5% |
| 10 | −0.047 | −0.030 | 64.2 | 78.6% |

单峰，峰值 6–8。更凶的一侧掉得很快：抢到的庄家位多，但**做庄打成率从 65% 掉到 54%**，
两头一抵消就是净亏 —— 这条曲线把 §3.1 那条「庄家位值钱」的机制量成了它的边界：
**愿意加价是对的，加到 50 分以上去抢就是错的。**

### 7.2 开叫门槛：与阶梯**有交互**，且门槛 8 几乎消灭全 pass 重发

| 门槛（阶梯固定为当时的默认 6） | 1 变体+2 基线 | 2 变体+1 基线 | 重发（A/A=354） |
|---|---|---|---|
| 8 | +0.057 | +0.020 | **32** |
| 10 | +0.048 | +0.025 | 120 |
| 11 | +0.036 | +0.025 | 198 |
| 12（当时默认） | 0 | 0 | 354 |
| 13 | −0.007 (ns) | −0.018 (ns) | — |
| 14 | −0.033 | −0.050 | — |

交互是真的：旧阶梯（12）下把门槛降到 6 是中性偏负（整局台 −0.58/−1.00），
新阶梯下降到 8–11 是正的。**两个旋钮不能各自调** —— 竞叫上限一变，「没人叫过时该不该自己开」的最优值跟着变。
顺带一个实用收获：门槛 8 把全 pass 重发从 354 次压到 32 次（每 18000 座位-副），
那正是 ADR-0015 当初把门槛从 15 降到 12 的动机。

### 7.3 2D 网格：最优是一块平台

| 阶梯＼门槛 | 8 | 10 | 11 | 12（当时默认） |
|---|---|---|---|---|
| 6 | +0.057 | +0.048 | +0.036 | 0 |
| **8** | **+0.060 / +0.048** | **+0.060 / +0.052** | **+0.056 / +0.055** | +0.021 / +0.030 |
| 10 | +0.024 (ns) | +0.006 (ns) | −0.011 (ns) | −0.047 / −0.030 |

（每格两个配比各 N=2000。平台是阶梯 8 × 门槛 8–11，约 +0.05~0.06；
对当前默认的**配对**比较在 N=6000 下为 +0.052~+0.066，MDE ±0.019。）

### 7.4 顺带否掉两个旋钮

- **`maxWilling` 85→95 的 Δ 恰好 0.0000**（两个配比、各 6000 副都是 0）：这个封顶在实践中**永远够不到**，
  是个惰性字段。它意味着「愿意分数」实际上由牌力分布的上端决定，不由封顶决定。
- `bidStepStrength` 2 / `bidStepPoints` 10 只是「更凶」的另一种写法（竞叫 ×1.16 / ×1.21），都更差；
  `bidStepStrength` 4 ≈ 0（不显著）。所以阶梯**斜率**不是独立旋钮，能动的只有原点。

### 7.5 换了没参与调参的种子复现：成立，但**没有达到事先门槛，所以默认没动**

复现批次（seed0=20000，N=6000，两个配比）：

| 候选 | 调参批次（1 起） | 复现批次（20000 起） |
|---|---|---|
| 门槛 8 + 阶梯 8 | +0.0663 / +0.0539 | **+0.0620 / +0.0534** |
| 门槛 10 + 阶梯 8 | +0.0579 / +0.0570 | **+0.0531 / +0.0544** |

跨批次、跨配比一致到 ±0.005 —— **不是过拟合**。但按事先定的四条门槛逐条核对：

| 条件 | 结果 |
|---|---|
| 机制计数非零 | ✅（开叫 ×1.38~1.74，重发 354→19~104） |
| CI 不含 0 | 单副台 ✅ 两个配比；**整局台 ❌**（1:2 时 +0.57 / +0.64，CI 跨 0） |
| Holm 校正后显著 | 单副台 ✅；**整局台 ❌**（2 个 p 值都过不了） |
| 幅度 ≥ +0.1 级/座位 | ❌（+0.052~+0.066，**只有门槛的六成**） |
| 整局台不为负 | ✅（正，但不显著；冠军份额 32.5%/69.4%，与公平份额 33.3%/66.7% 基本齐平） |

**所以不采纳。** 这跟第 4 节里「有意偏离门槛」那一次不一样：那两项是「显著 + 机制清楚 + 整局台同向」的
打得更对的改动，而这是**在阈值以内、整局台测不出显著**的同一类旋钮的细调。更重要的是，
它带来的 +0.06/座位/副 只有「选对方向」那次晋升的 +0.28 的**五分之一**，
而在平台上继续抠下去就是追噪声了。

这一轮真正的收获不是那 +0.06，而是**把曲线画出来了**：默认值（门槛 12 + 阶梯 6）落在最优平台旁边
（离平台差约 +0.06/座位/副，即原晋升幅度的 20%），而**更凶的一侧在 8 之后迅速变差**
（0→2→4 一路 −0.12/−0.08/−0.04，做庄打成率掉到 54%）。也就是说 §3.1 那条机制的边界被量出来了。

### 7.6 一条必须更正的读数

精细扫描的中间版本里我说过「精调候选在竞叫上更温和（竞叫 ×0.97），可能更好打也更耐玩」。
**这句是错的。** 竞叫次数确实是 0.97×，但那是因为它**改成用开叫而不是用抬价去拿庄家位**（开叫 ×1.38）；
按同一个参照物量「抢庄」的真身：

| 局面（单副台 6000 副，同一个参照物） | 拿庄家位的比例 |
|---|---|
| 1 个当前默认座位 + 2 个历史基线座位 | 51.0% |
| 1 个精调候选座位 + 2 个历史基线座位 | **55.2%** |
| 1 个历史基线座位 + 2 个当前默认座位 | 17.1% |
| 1 个历史基线座位 + 2 个精调候选座位 | **15.9%** |

精调候选**抢得略多**，不是略少。竞叫次数这种「过程计数」不能拿来代替「结果计数」——
这条后来写进了 §1 的方法表（机制计数只用来证明开关接线，不用来论断强度）。

  之前 `undefined` 只能当其中一侧，把对照方向锁死（坑过两次：一次量不出「晋升前后」，
  一次量不出「候选 vs 当前默认」）。

## 8. 真实对局诊断：用户报的四条打法缺陷（ADR-0018）

用户打完一轮真实对局（表 8 `EZ2D5S`：1 人 + 2 机器人，13 副）之后报了四条打法毛病。
逐条对账的结果是：**四条都真的发生了**，但**只有一条的修法真的更强**。

| # | 指控 | 机器侧实例 | 修法 | 实测（2000 种子 × 两配比） |
|---|---|---|---|---|
| 1 | 坐庄送副 K（不打 A） | d4#9 ♠K 丢 20、d6#4 ♣K、d6#8 ♥K | 兜底不领赢不了的带分牌 | −0.036 / −0.044 ✗ |
| 2 | 有顺子不逼顺 | d6#0/#1 双王分两轮单出 | **主牌顺子整段领出** | **+0.037 / +0.038** ✅ |
| 3 | 清主积极性不高 | d3：8 张主全程没吊，一副 0 分 | 长主也吊 / 钓王 | −0.086 / −0.092 ・ −0.042 / −0.040 ✗ |
| 4 | 闲家放庄家小牌走 | d4#2 ♥Q 领、出 ♥5 送 5 分 | 省分选牌（四版） | −0.018 / −0.024 / −0.038 / **+0.014** |

② 已提升为默认（复现批次 +0.019/+0.022；整局台 +1.11/+1.02，两个配比都过 Holm；
**庄家打成率 66.1% → 68.6%**）。③ 的两种修法都更差，而且方向一致：拿一张**不是必胜**的顶主去吊，
被对手的王吃掉，白送一张最大的主。

**为什么"听起来都对"的修法大多是负的**：三条失败修法的共同点是**省着用牌**（留 K、留 5、留着主不领）。
但在这个计分规则里**闲家抓到的分完全不计分** —— 把一张死牌留在手里并不能从庄家账上拿走任何东西，
那张牌迟早要垫出去；你付出的却是节奏与手牌结构。唯一为正的那条恰好相反：**一次花掉两张牌换节奏**。

④ 的四版迭代本身也是一条教训：前三版**在同伴已经赢定时也生效** —— 那正是该把 5 分垫给同伴的时候
（`feedPartner` 就干这个），于是"省分"把喂分抵消掉，计分器显示送出去的分反而**变多**（1.01–1.07×）。
限定成「只有这一墩正被对手拿着时才省分」之后才降到 **0.93×**，但叠在 ② 之上是 −0.011（不显著），
所以不采纳。

### 8.1 「人类这轮手气好」这个解释能走多远

有人问：机器人这一轮显得惨，是不是因为人类做庄的手气确实好？用**机器人自己的** `strengthOf` /
`willingPoints` 逐座位复核（不是手抄一份，见 `data/_analysis/bid-audit-runner.mjs`）：

| 复核项 | 结果 |
|---|---|
| 叫牌有没有漏 | **该开没开 0 次、该竞没竞 0 次**（13 副里每个 pass 都符合它自己的门槛） |
| 人类做庄的 7 副 | 人类牌力 **14.7**，两个机器人 11.6 / 9.0 —— 人类确实是强的一方 |
| 机器人做庄的 6 副 | 机器人自己牌力 **17.8**，人类 11.5 —— 机器人也是强的一方 |
| 结果 | 人类做庄 7/7 打成（最终分 75/90/90/55/50/80/120）；机器人做庄 **2/6**（35/55/0/15/60/25） |

所以手气**能解释一部分**：人类在 7 副里拿到强牌（14.7 vs 11.6/9.0），而这几副对手很弱（6~13），
于是没人抬价、人类以 40 分低价拿庄（d7/d8/d11 都是「开 40、两家 pass」）并打出 90/90/80；
底牌保底也贡献了不少分（d13 底 20×4 = +80）。

但它**解释不了机器人做庄为什么差**：机器人做庄时的牌**更好**（17.8 vs 14.7，将门 8.3 vs 5.9 张），
却只打成 2/6。而且叫牌本身没有失误（0 次漏叫），所以「人类抢到庄」不是机器人叫牌被动了 ——
那几副它确实没牌。

**统计警告**：13 副、7 副这样的样本，7/7 对照 bot 对 bot 的 66% 做成率是 p≈3.6%，
「异常」是显著的，但**分不清技术还是运气**。这正是为什么策略结论只由竞技场的几千副来定，
这 13 副只用来**提出假设**（以及验证修法在那一副上是否真的改了行为）。
