# MCP 默认负载只给「此刻行动所需」：跨副不再累积，记忆成为考题

ADR-0011 把逐字负载压成了紧凑投影，一副牌从 116,278 降到 35,636 字符 —— 但那条路的默认假设仍是
**每条负载自包含**：整份 `trickHistory`、跨副 `history`、整块座位卡，每帧照发一遍。
宿主每个请求都重发整段会话，所以模型**已经看过**那些帧；再投喂一遍是纯税，而且乘在回合数上（二次）。
这一条把默认负载的判据换掉：**只给此刻行动所需的，加上自上次看到以来新发生的事**。

## 决策

1. **默认（`verbose: false`）只给「行动投影」**（`packages/mcp/src/project.ts`）：
   - **留**：`turn`（canAct / 短 hint / legalBids / legalPlay）、`you`（手牌等）、本副规则三件套
     `trump`/`contract`/`declarerSeat`、当前墩、`capturedPoints`/`handCounts`、结算帧的 `summary`；
   - **砍**：跨副 `history` 与 `historyOmitted`、`view.progress`（可由 `levels` 推）、`view.version`、
     整块座位卡（改成挂在座位下标上的 `names`：`["甲","乙","丙"]`）、`table.code`/`view.dealNo`/
     `view.dealerSeat`/`turn.phase`/`turn.isYourTurn` 这些字面重复（`isYourTurn` 与 `canAct` 在每一个
     分支里同值）；
   - **`trickHistory` 只留最近完成的一墩**（`TRICK_TAIL = 1`）。在座玩家每副出手一次，两次出手之间
     **恰好**多完成一墩，所以末墩永远是「新发生的那件事」、零重复；它不是可有可无的：你出手时第三家
     还没出牌，他那一张**只可能**从末墩看到（赢家可由「当前墩的 leaderSeat」推出，分可由
     `capturedPoints` 增量推出，但那张牌推不出来）。
2. **阶段门控代替「只发一次」**：`auction`/`highestBid`/`dealerSeat` 只在叫牌阶段给（成交后它们冻结，
   结论由 `contract`/`declarerSeat` 带走）；`levels` 只在大厅、本副结算、终局这些「级别正在变」的帧给。
   **`/api/mcp` 是无状态的**（ADR-0010：每个请求新建服务器、不发会话 id），任何「这条已经发过了」的
   字段都得靠服务端记住客户端看到了哪 —— 那条路被明确拒绝。所以省的办法只有两种：**删掉**
   （模型看过就不必再给）与**阶段门控**（形状仍是负载自身的纯函数，同一份负载永远同一形状）。
3. **`verbose: true` 从「兼容逃生门」升格为「中断恢复通道」**：对话被截断、换了个会话、或模型自己
   觉得记不清时，用它拿回引擎类型逐字的那一份（座位名字、级别、全部牌史都在里面）。
   `SERVER_INSTRUCTIONS` 明说这件事，否则模型不知道自己被截断了。
4. **`read_rules` 补两个参考键**（`packages/engine/src/help.ts` 的 `trump-order` 与 `runs`）：
   主牌大小顺序（有主/无主/副牌跳级/平张先出为大）与顺子完整规则（跳级牌、主牌全序相邻、至多一张
   副级、赢墩需同长单段、杀牌与垫牌）此前只在 `/rules` 的散文与引擎注释里 —— 工具面的模型一个字都
   拿不到。它们是**参考键**：进 `HELP_KEYS`（`read_rules` 全量读法给出），但 `helpKeyOf` 永不返回，
   所以网页「?」弹层不长一行（弹层刻意只讲「此刻该干什么」）。顺带修掉两处旧账：`play-wait` 里
   从未定义的「层号」一词，以及 `help.ts` 头注释「/rules 也读它」的过头话（`/rules` 是另一份长文）。
5. **`instructions` 加一句认证推断**：除 `read_rules` 与 `claim` 之外任何一次调用没被「还没有身份」
   拒绝，就说明这个连接已带有效凭据 —— 不要再让用户去配置凭据。防的是「会话开始时是**无身份会话**、
   人类配好凭据重连之后，模型照着旧说明一直催配置」。

## 实测（座位 0，RNG 固定；`payload-budget.test.ts` 的同一套记账）

| 指标 | 逐字（0010） | 紧凑（0011） | **行动投影（本条）** |
| --- | --- | --- | --- |
| 一副牌实收 | 116,278 | 35,636 | **18,453** |
| 一副牌累计读入 | 1,845,222 | 401,156 | **288,904** |
| 结算单帧 | 6,232 | ~2,760 | **1,355** |
| 整局实收 | — | 396,503 | **139,207** |
| 整局累计读入 | — | 26,710,960 | **11,333,093** |
| **整局最大单帧** | — | 4,402（随副数涨） | **1,393（基本不动）** |
| 每副调用数 | 38 | 21 | 21（不变） |

最要紧的一格是**整局最大单帧**：0011 那一版它随副数线性上涨（每副多一行战报、整份牌史重发），
现在战报与旧墩都不再进默认负载，所以「第几副」不再影响单帧大小 —— 预算测试里由一条**相对**断言
钉住（`TWO_DEALS.maxMessage <= BUDGET.maxMessage + 60`），而不只是绝对上限。

## 取舍与后果

- **记牌能力不再靠负载兜底**：这是**有意**的 —— 记牌、记战报属于牌手能力，属于要考的东西。
  代价是「模型忘了」与「根本没给」在观感上不再可区分；缓解手段是 `verbose`（恢复）与
  `capturedPoints`/`handCounts`（可核对的账）。
- **砍掉的字段没有一个是不可恢复的**：`verbose: true` 仍然给出引擎类型逐字的那一份，
  浏览器那条路（`/view`、SSE）一字未动。
- **类型上弱了一点**：阶段门控字段是 `?`（`deal.auction?: …`），消费方要么分支内断言、
  要么 `?? []`（`mcp-check` 与预算测试都这么改）。这是诚实的信号 —— 「只有叫牌阶段才在」。
- **预算上限按实测收紧**（一副实收 19,500、结算单帧 1,500、整局累计 12,000,000），余量 5-10%；
  「多一次调用」仍由 `CALLS_LIMIT` 单独把守。按 AGENTS 规则 9 做过注入实验：把 `TRICK_TAIL` 改成 4、
  并去掉叫牌门控，**11 条测试变红**（末墩三条 + 字段清单 + 门控纯函数 + 成交结论 + 五条预算），
  逐字节还原后 94 条全绿。
- **`write` 的路径没变**：动作仍然一次都不重试（ADR-0012）；这条只动**读**的出参形状。

## 与旧 ADR 的关系

- **收窄 ADR-0011**：那条的「紧凑投影 + `verbose` 逃生门 + 动作自带等待 + 合法性由状态给」四条仍然
  成立，被换掉的是默认负载的**判据**（自包含 → 行动所需），以及「记牌能力不削」这条取舍 ——
  现在明确**削**（换成交互成本）。
- **收窄 ADR-0010**：那条的「引擎类型逐字」早已被 0011 收窄；这里再进一步 —— 默认出参不再是
  「同一份负载的省字说法」这种逐字段对应关系，而是「该给什么」的取舍（`names` 甚至换了承载方式）。
  单向派生与「不许有第二个来源」两条纪律不变，静态守卫照旧钉着。
- **`help.ts` 的唯一来源地位**在 ADR-0010 里写作「web 的「?」弹层、`/rules` 与 `read_rules` 共用」；
  实际 `/rules` 是另一份长文（只有 `ActionBar` 读 `help.ts`）。本条把这个说法改正为
  **紧凑层**（弹层 + `read_rules`）与**长文**（`/rules`）两份，靠 `anchor` 对应。
