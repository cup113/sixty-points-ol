# 规则演示做成应用内幻灯片，不做视频

> **状态**：已被 ADR-0025 取代 —— 幻灯片页整体改为交互式新手引导（概念简述 + 测验 + 引导局），三副编排故事随之退役。深链 `?s=` 的机制被新课程继承；「自动播放」与「种子↔牌局钉死」没有继承。

`/learn` 是「基本概念 + 实战牌局」两半的演示页：概念章 15 屏（我写，示例全部取自 `scenarios.ts` 里已被 `tutorial.test.ts` 用引擎核对过的数据），牌局章三副（牌手本人在 `/studio` 打出来并逐步讲解，见 ADR-0008）。做成网页幻灯片而不是导出视频，三个理由。**其一，内容会变**：规则讲解是最容易过期的东西，视频一改就得重录，而页面只改数据源；幻灯片本来就是它的正经形态，录像只是它的一种导出格式。**其二，每一屏都能深链**（`/learn?s=245-trick-8`），分享给牌友能直接落在「那一墩」，视频做不到。**其三，可被测试守住**：`deck.test.ts` 盯结构（每一墩恰好一屏、深链都能定位、文案无禁忌），`deal-story.test.ts` 盯内容（生成物 == 现场重算、作者原话逐字保留），`ui-check` 盯出货产物。视频没有这些。

有一处实现值得记下来：**深链用查询参数 `?s=` 而不是只认 `#hash`**。hash 只在浏览器里有效，SSR 时读不到，那样每一屏都得先渲染封面再靠 JS 跳（首屏闪、分享链接无预览）。查询参数在服务端就能算出来，所以 `+page.ts` 的 `load` 提供它，页面把第一屏直接渲染成那一屏；翻页过程中再用 `history.replaceState` 把 hash 同步上去（不往历史里塞六十条记录）。

概念章不新造事实：所有示例都来自 `scenarios.ts`，那里每个牌面示例都被引擎函数核对过（`tutorial.test.ts`）。牌局章只读生成的故事数据（`stories/<slug>.ts`），页面渲染**不跑回放、不碰随机数**——生成物里牌面与事实都是烘焙好的，所以引擎或 RNG 将来变了，已发布的讲解也不会跟着变味；真要变，是 `deal:check` 报红、由人决定重新生成。

代价：三副牌的讲解里，我补写与改写的部分最多只能做到「像他本人的语气」（`docs/deals/<slug>.review.md` 逐条留痕供他复核），而语气这种事无法用测试判定；交互手感（翻页、自动播放节奏）也只能由人过一遍。另外幻灯机是纯客户端状态，没有 JS 时只能看到第一屏。
