# 出牌那一手：必出的自动选中，凑不出的点了不响应

跟一张牌在真实牌局里是**一次点击**的事，在这块界面上却常常是两三次：轮到你、看蓝框、
把该跟那门里的那张点起来、再按「出 牌」。而绝大多数跟牌其实是**没得挑**的 ——
该门只剩一张、或者该门正好够张数且只有一种合法结构。反过来，手点得快的时候还容易点到
**凑不出合法结构**的那些牌，于是托盘弹一句「跟牌结构不足：应按最长顺子优先出牌」，
你得先撤掉、再重点。这两件事浪费的是同一个东西：**一手牌本来就已经决定了的那部分**。

ADR-0021 把可点的**时机**放宽到了「没轮到你也能点」，但把合法性留在了出手那一刻
（「拟选不做提前校验」）。这一条把合法性**提前到点击那一下**，一次解决两头。

## 决策

1. **判据进引擎，界面不自己算**（`packages/engine/src/validate.ts`）：
   - `forcedPlay(hand, trump, lead)` —— 跟牌时**不用挑**的那几张。该门不够 n 张时是手上该门的全部
     （其余自由垫）；该门够 n 张时**只在唯一一种合法组合**时给出，有多种组合就给空集；
     领出恒为空。
   - `pickableCards(hand, trump, lead, selection)` —— 现在点得动的那些（`cardKey` 集合）：
     「加上它或取消它之后，仍然凑得出合法的一手」。必出的几张撤不掉；该门够张数时别的门一张
     都点不动；该门够张数时加进去之后必须还凑得出结构优先的那一手；张数满了不再收。
2. **两处判据与裁判同源**：都是 `compareProfiles(segments(cards), bestProfile(holding, n))`，
   一个字都不另写。合法性只能由「段长分解」决定，而「这张牌能不能点」问的是**存在性**
   （加了它之后还凑不凑得出），没有闭式答案 —— 所以按 n 元子集**枚举**。可达的最坏是主牌门：
   一副 54 张里 18 张主牌，领出 5 张 ⇒ 我手上最多 13 张 ⇒ C(13,5) = 1287 个子集
   （本机实测一次枚举 **4 ms**，见下）。撞上 `PICK_SEARCH_LIMIT`（2 万次检查）时**放行**：
   宁可让服务端在出手那一刻拒一次，也不许因为一次没算完的搜索把手牌锁成点不动。
3. **自动选中是「玩家没表态」时的默认值**，不是另一个状态位：
   `TableClient` 里 `#custom: string[] | null`（`null` = 没点过），`selected = #custom ?? #forced`。
   玩家点第一张起就写进 `#custom`，必出牌不再接管；「清 空」写的是 `[]`（明确的「一张都不选」）
   而不是 `null`，否则必出牌会立刻把它填回来。清回 `null` 只有一条路：手牌变了
   （换副、补位、我刚出手 —— 判据仍在 `selection.ts`）。
4. **点不动的牌是「不响应」，不是「报错」**：`toggle()` 直接 return，`HandFan` 抖一下（复用既有的
   `@keyframes shake`），光标是禁止符号，悬停不上浮。**牌面不调暗** —— 「该跟哪一门」已经由蓝框
   说了，再暗一层就是第二套语言。
5. **自动选中只在「这一手归我动」的那一刻发生**，点得动只在本墩**还欠我一手**时生效
   （两个布尔分别是 `TableClient.myMove` 与 `.planning`，动作托盘读的也是前者）。
   这一条是**修订**：第一版写的是「两样都不看是不是轮到我」，验收时当场坏了（见下）。
6. **埋底不在此列**：那一段是「20 张里挑 3 张」，没有「点了也不成」的约束，`pickable` 为 `null`
   = 不设限。

## 修订：自动选中挂错了前提（验收当天）

第一版把自动选中的前提写成「本墩已有领出」。它是**一半**的前提 —— 缺的那一半是
**「这一手归我动」**。于是有两个窗口会走火，而两处都表现为「牌自己上浮、却没有托盘」：

- **别人领出的那十几秒**：蓝框已经标出该跟哪一门（拟选，ADR-0021），必出牌再把它整族上浮一次 ——
  同一件事两套语言，而且上浮那一套更强，读起来像「系统替我选好了」；
- **我自己刚出完牌**：领出还是**上一手**的，我的手牌却已经变了，`forcedPlay` 于是从新手里
  挑出一张「必出」并上浮 —— 那张牌与这一墩已经没有关系了。

根因是同一个：**「我的回合」被在三处各算了一遍**（托盘的 `visible`、页面的 `selectable`、
`#forced` 的隐含前提），三处各自写了一部分条件。现在收成一个布尔 `myMove`（打牌轮到我 /
埋底轮到庄家），托盘、手牌可点、自动选中都读它；「拟选窗口」收成另一个布尔 `planning`
（本墩已有领出 **且** 我的牌还没落到桌上），蓝框与点得动读它。

后果之一要写下来：**我出过手之后，本墩剩下的两家里自己的手牌不可点**（`planning` 为假）。
那是一段一到三秒的空窗，换来的是「旧领出不标我的手牌」—— 而在此之前，那一段里点牌
既标错花色、又凑不出下一墩的任何东西。

### 同一轮的第二个修订：`forcedPlay` 没有守「撞上限就放行」

`eachLegalFollow` 有三种结局（`done` / `stopped` / `exhausted`），而第一版只有
`pickableCards` 看了它：`canCompleteFollow` 撞上限时返回 `true`（放行），
`forcedPlay` 却把「枚举被截断前只找到一种」当成「只有一种」，直接把它当必出牌交出去；
紧接着 `pickableCards` 按「必出不能取消」把这几张锁住。两个消费者对同一个返回值给出了相反的语义 ——
而这句「撞上限就放行」在探针注释与本文第 2 条里各写了一遍。

现在两处读的是**同一份结果**：`legalFollowSets` 一次枚举出「有哪几手合法」，
截断时返回 `null`，两个消费者都按 `null` 放行（必出为空、整手可点）。
顺手也修掉了它的性能形状：原来 `pickableCards` 对**每张候选牌**各枚举一遍、
`forcedPlay` 再自己一遍，可达最坏的手牌上实测 **24 ms 一次**；现在一次枚举，
同一副手牌 **4 ms**，常见手牌 ≪ 1 ms。

## 取舍与后果

- **自动选中会让人以为已经出过牌**。所以托盘那句「已选 N 张」保留，出手仍是人按的那一下 ——
  自动只到「选中」，**从不自动出手**（那一步没有撤销可言）。
- **正解：玩家自己的选择更长命**。拟选那几张跨墩保留（ADR-0021），`#custom` 因此也跨墩保留；
  它可能在新领出下变成不合法，那时托盘会给出原因（`playError` 仍在，退成兜底），
  而**撤掉它总是允许的**（只有必出牌撤不掉），不会把人卡在一个撤不掉的非法选择上。
- **「清空」之后必出牌不回填**。这是刻意的：清空是一次表态，下一帧又填回来会像按钮坏了。
  要回到自动态，换副或出手一次即可。
- **枚举是有代价的**：可达最坏 1287 个子集、本机 4 ms 一次（这副手牌是「我持 13 张主牌、
  别人领出 5 张主牌」），常见手牌是几十个子集、亚毫秒。它只在「选择或局面变了」时重算一次
  （`$derived`），不在指针移动时算 —— 所以**悬停永远不触发它**。
- **`playError` 不再常走**：只可能因为「换了领出、旧拟选还挂着」而出现。它没有被删 ——
  服务端仍然是唯一裁判，本地那句是同一套规则的提前告知。
- **守卫**：`packages/engine/test/pick.test.ts` 里除了逐例断言，还有一条**穷举交叉校验** ——
  把该门每个 n 元子集分别交给 `checkPlay` 与「一步一步点得动吗」，两者必须逐一对上
  （`点得动 ⇔ 裁判说合法`），外加「必出的那几张恒在每一手合法牌里」。
  `apps/web/test/forced-selection.test.ts` 钉渲染层那几条接线（含上面那次回归：把
  `if (!this.myMove) return []` 去掉，它就会红；以及不许把 `transform: none` 写到
  已选中的牌上 —— 必出牌正是「既已选中、又点不动」的那一族，那一下会把牌放回底部 26px），
  `trick-leader.test.ts` 钉「现在最大」，`svelte-check` 管类型与 a11y。

## 与旧 ADR 的关系

- **收窄 ADR-0021 第 4 条**：「合法性仍然只由托盘判」不再成立 —— 现在点击那一下就用同一个引擎
  判据拦了。托盘的 `playError` 留着兜底，判据本身没有第二份。
- **再次收窄 ADR-0021 的窗口**：拟选从「本墩已有领出」收成「本墩已有领出 **且我还没出手**」。
  理由不是省事，而是「该跟哪一门」这句话在我出过手之后就不成立了。
- **不动引擎的规则**：`validateLead` / `validateFollow` / `checkPlay` 一字未改，新增的两个函数
  只是把同一句话用在「点之前」。服务端权威与「写路径不重试」都不受影响。
- **不给 MCP 工具面加东西**：`check_play` 已经回答「这手行不行」，模型不需要「哪几张必出」——
  那是省点击的事，模型没有手指。
