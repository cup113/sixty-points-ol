# 0022 · 一副结束时的三拍：看清末墩 → 亮底牌 → 弹结算

状态：已接受（取代「收墩即弹结算」的默认行为）

## 背景

末墩收墩的那一刻，`deal.summary` 就出现在负载里，而结算弹窗是 `fixed inset-0 z-50` 的一层
—— 于是它**在一帧之内盖住整个毡面**。被盖住的是这一副最该看清的两样东西：

- **末墩**：谁赢了这一墩决定 **底牌倍数 x**（庄家方赢 = 加，闲家方赢 = 扣）；
- **底牌**：那 3 张的点数决定**保底还是抠底**、以及乘出来的分。

这两句话结算弹窗里都写得清清楚楚（`ScoreEquation` 的算式、`VerdictBadge` 的结论），
但玩家得先**看见**这两件东西，才读得进去那句话。真机验收时的原话是：
「末墩完成后，先让用户看清楚牌，再给一个亮底牌时间，再弹窗」。

另外一件事在动手前必须先看清：「下一副 / 开新对局」**不只在弹窗里** ——
`phase === 'scored'` 时操作条那一行本来就有这两颗按钮（`ActionBar`）。
所以「弹窗还没弹，谁都点不到下一副」是**错的**；真正要管的是那两颗按钮的时序。

## 决策

1. **三步的推进方式：定时自动 + 可点击提前。** 无人操作时节奏恒定（每副都一样），
   想快点看结算的人点一下「跳过」即可 —— 不必把「要不要继续」交给玩家，
   也不许把人钉在屏幕前等。
2. **两段时长写死**：看清末墩 **2.0s**、亮底牌 **3.2s**（合计 5.2s），与
   `CLOCK_STALE_SECONDS` 同类：它们是「让人看完」的粗估值，不是可按桌子调的参数。
   参照物是机器人拟人延迟 0.5–1.5 秒 —— 三拍是在一次**收墩**之后，不是每一次出牌之后。
3. **每副都走**（含对局的最后一副）。节奏一致，玩家不用判断「这一副会不会弹」；
   最后一副只是弹窗里多一块「对局结束 · 冠军」。
4. **观战者一样走三步。** 他们看得更专注（没有手牌要选），末墩与底牌同样值得看清；
   一套节奏、一条守卫，不为观战另开一条路径。
5. **「下一副 / 开新对局」锁到 5.2s**，**跳过不解锁**：跳过只提前**自己**看结算，
   而换副是**全桌**的动作（服务端换副，所有人一起进下一副）。
   少了这把锁，一个跳得快的人在 ~0 秒就能开下一副，别人正在看的末墩与底牌就被切走了。
   锁上之后全桌节奏一致，而且**不需要任何新通道**：每个人的锁都从「自己第一次看到这一副结算」
   起算（本地时钟），各浏览器之间的偏差只有 SSE 投递那几十毫秒。

## 实现要点

- **时间不进引擎**：三拍是纯 UI 时序（`labels.ts` 的 `scoredStepAt` / `nextDealUnlocked`
  是纯函数，组件只按本地时钟读它）。服务端不知道三拍这件事，负载里也没有任何新字段。
- **`summary.kitty` 本来就是公开的**：引擎在结算阶段把**埋下的底牌**给所有人（观战者也有），
  所以「亮底牌」不涉及任何新的可见性 —— 它只是把公开信息**按顺序**摆出来（早 3.2 秒）。
- **跳过是「一次点一拍」**（`nextStep`），不是「一次跳到结算」：第一拍那颗按钮写的正是
  「看底牌 »」。两路状态（时钟 / 手动）取**较后者**（`laterStep`），点完不会被时钟反超。
- **重载 / 补位也重走三拍**：`scoredDeal` 只在内存里，刷新之后从 0 起算。
  代价是刷新后多等 5.2 秒才看到弹窗，换来的是**一条路径** —— 任何时刻进入结算，
  看到的都是同一套节奏，而不是「首帧就弹、刷新才走三拍」那种随缘行为。
- **换副即收敛**：`summary` 变回 null（下一副已发牌 / 全 pass 重发 / 回大厅）时三拍作废，
  不留残留的提前态。
- **「结算详情」按钮一直在**：那 5.2 秒里它是唯一能手动打开弹窗的入口（弹窗还没自己弹），
  所以它不能跟着锁 —— 锁只锁「换副」那两颗。

## 实测（`pnpm shot`，带浏览器的**时间轴**采样）

三拍的判据不可能靠「量一帧」：它要的是**顺序与节奏**。所以这两屏每 120ms 采一帧，
把「哪一拍、亮底牌层在不在、弹窗在不在、下一副锁没锁」记成序列再断言。

| 判据 | 15-scored-pacing（桌面，纯自动） | 16-scored-pacing-320（320px，点 2 次跳过） |
| --- | --- | --- |
| 末墩（第一拍） | @0.00s | @0.00s |
| 亮底牌（第二拍） | **@2.08–2.17s**（停 2082–2167ms） | **@0.13–0.14s**（点了跳过） |
| 弹窗（第三拍） | **@5.35–5.39s**（亮牌停 3181–3311ms） | **@0.63–0.68s**（点了跳过） |
| 「下一副」解锁 | @5.35–5.39s | **@5.15–5.24s（仍等满两拍）** |
| 亮底牌那一块 | 156×94px | 134×83px |
| 与三个出牌点的相交 | 0 | 0（内容槽 331px） |

第 16 列就是决策 5 的证据：跳过把**自己**的两拍压到 0.68 秒，而全桌那把锁仍然守到 5.2 秒。

## 守卫

- **单测**（`test/labels.test.ts`）：`scoredStepAt` 三拍边界逐个数（1999/2000/5199/5200）、
  `nextDealUnlocked`（含「坏输入一律当没解锁」）、`nextStep` / `laterStep`（一次一拍、只许往前）
  + 一条**永久反证**（三拍必须真的分得开、顺序不能颠倒、两拍都不能是 0、亮底牌不得短于停顿）。
- **源码守卫**（`test/table-chrome.test.ts` 的 `scoredPacingCheck`，六条 + 七条反证）：
  ① 弹窗由第三拍驱动（不是「summary 一到就弹」）；② 亮底牌层两个钩子分挂两层、让开点击、
  里面不许有可点元素；③ 跳过住操作条那一行、且只在结算阶段出现；④ 锁在**两处**都上
  （操作条 + 弹窗），并且页面真的把 `nextDealReady` 传给了两者；⑤ 跳过接 `nextStep`、
  两路合并走 `laterStep`；⑥ 起算那个 `$effect` **不许返回清理函数**、叫醒时钟必须清理且敢停、
  页面里不许出现裸的时长数字。
- **出货 HTML**（`scripts/ui-check.ts`，跑在构建产物上）：把一整副打完，在结算首帧断言
  「有『看底牌 »』入口、**没有**亮底牌层、**没有**弹窗、『下一副』带 `disabled`」。
- **几何 + 时间轴**（`scripts/shot-auction.ts` 的 `runPacing`）：三拍依次出现（早于顺序、缺拍都红）、
  第一拍里不许有底牌与弹窗、两拍停留与常量相符（容差 500ms）、解锁不得早于两拍之和、
  亮底牌那一块在内容槽里且与三个出牌点**零相交**、页面**不许有未捕获错误**；
  并且把**原有那一整套版面判据**也在这一屏上跑一遍（三拍走的是另一条采样路径，
  少了这一句结算屏会成了唯一没人量的版面）。

## 这一轮自己踩的四个坑（都留成了守卫）

1. **`$effect` 返回清理函数 + 每帧重跑 ⇒ 三拍永远停在第一拍。**
   `summary` 每收到一帧 SSE 就是新对象，于是起算那个 effect 每一帧都重跑；带清理函数的写法
   会在重跑时掐掉定时器，而早退分支又不会重建它们。**单测与源码守卫都看不见它**
   （它们守的是接线），是 `pnpm shot` 的时间轴抓出来的：采样 112 帧、三拍一步没动。
   现在起算与叫醒拆成两个 effect（前者不返回清理、后者每次重建 interval），并有源码守卫钉住。
2. **一次点击直接跳到结算，会把亮底牌那一整拍吃掉** —— 而第一拍那颗按钮写的正是「看底牌 »」。
   是 shot 的「点了『看底牌»』但亮底牌仍在 2317ms 才出现」抓出来的。
3. **钩子挂错层**：`data-kitty-reveal` 一开始挂在 `absolute inset-0` 的定位壳上，
   几何判据于是量出「底牌块 1137×600px、压住三个出牌点 104045px²」。现在两个钩子分挂两层
   （`data-kitty-layer` 定位壳 / `data-kitty-reveal` 那块牌匾），源码守卫也会拦这种挂法。
4. **判据写成「弹窗首帧必须禁用」是错的**：自动那一路的弹窗正好出现在解锁那一刻（5.2s），
   那时它当然已经可点。正确的写法是**按时刻**判：「在解锁时刻之前出现的弹窗，锁必须是合上的」。

## 取舍与后果

- 每副多花 5.2 秒才看到结算。想快的人可以连点两次「跳过」提前读结算，但**换副仍要等满** ——
  这是决策 5 有意买下来的：全桌节奏优先于个人手速。
- 刷新 / 断线重连之后会**重走**三拍（多等 5.2s），换来的是「任何时刻进结算都是同一套节奏」。
- 亮底牌那一拍的牌宽取 46px（桌面）/ 40px（窄屏），比结算算式里的 26px 大、比出牌堆的 56px 略小：
  这一拍的任务是「看清这 3 张是什么牌」。它与三个出牌点零相交是**量出来的**（不是估的）。
- 三拍期间玩家仍可正常用「结算详情」翻结算、用「上一轮」回看末墩 —— 三拍只延迟**自动弹窗**，
  不冻结任何入口。
