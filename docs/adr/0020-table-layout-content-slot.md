# 毡面改成三行格：内容槽 + 动作带，座位卡只剩身份

牌桌页的毡面此前是**一堆各自绝对定位的层**：三张座位卡钉在四角（`left-3 top-3` / `right-3 top-3` /
`bottom-3 left-3`）、阶段状态条 `top-[5.5rem]`、埋底面板 `top-[12%]`、叫牌面板 `top-[22%] max-h-[56%]`、
出牌点 `left-[6%] top-36` 与 `right-[20%] top-56`、动作托盘 `absolute bottom-full` 钉在操作条上沿、
动作带不存在。每个层都自己算偏移，**谁也管不了谁** —— 于是真机上出现了这一组相互压住的重叠：

| # | 现象 | 根因 |
| --- | --- | --- |
| 3 | 座位卡太高，与状态条上沿重叠 | 卡片底下多了一整行「请离 / + 机器人」 |
| 4 | 动作托盘压住「我」那张座位卡 | 托盘钉在操作条上沿，而那 40px 整根落在毡面的最后 40px 里；与我卡竖直重叠 32px、水平重叠 84px |
| 5 | 状态条压在座位卡与出牌区上 | 「定约 / 庄已抓」与卡片各算各的偏移，短屏上正好撞在一起 |
| 7 | 桌面端不错位、窄屏错位；>4 张顺子时仍然重叠 | 出牌点靠 `top-36`/`top-56` 的上下错位躲碰撞，而桌面端左右两点**同一高度** |

这一条把「不重叠」从**调数**变成**结构**：毡面是一个三行格，非座位层只能住在中间那一行（内容槽），
动作控件搬出毡面。同一批改动还修掉两个「只能量出来」的缺陷（见「实测」）。

## 决策

1. **毡面 = 三行格**（`grid grid-rows-[auto_minmax(0,1fr)_auto]`，钩子 `data-felt-row="seats" | "slot" | "me"`）：
   - **顶行**两张对手卡（`flex justify-between`，走正常文档流，不再自己定位）；
   - **内容槽**（`min-h-0`）：阶段状态条、叫牌面板、出牌区、埋底面板、大厅面板**全部**住在这里。
     「两个层各算各的偏移而互相压住」因此在结构上不可能 —— 槽的上下界就是它们的上下界；
   - **底行**「我」那一条**底栏**（跨宽一行装完身份：庄冠 / 头像 / 名字 / 级别徽标）。
2. **座位卡上的动作面撤到抽屉「牌桌」页**：`SeatCard` 不再有 `canAddBot` / `onAddBot` /
   `canRemoveBot` / `onRemoveBot` 与那一行按钮；`TablePanel` 长出「+ 机器人 / 请离」。
   理由是那**一整行**正是卡片比对手卡高、进而压住状态条与叫牌面板的直接原因；
   而机器人动作本来与入座/离座同类（改的是空座，不是牌局动作），所以「动作面不进抽屉」这条不变式
   收窄为「**牌局动作**不进抽屉」（叫品/埋底/出牌/结算）。请离的确认弹窗仍挂在**页面级** ——
   抽屉有 `transform`，`fixed` 弹窗会被困在里面。
3. **机器人头像换成内联 SVG，删掉「机器人」徽标行**：头像自己就是标记，名字前缀「机器人·」是
   **身份名**（服务端给的），照旧保留。不用 emoji（各平台字体不同、有的会渲染成彩色图片，
   在 36px 的圆里尺寸与基线都不齐）。
4. **动作带**：毡面与操作条之间加一条**常驻**的 44px 空带（`data-action-band`），动作托盘住在里面
   （`absolute inset-0` + 居中）。托盘不再钉在操作条上沿 —— 那一带必须有个明确归属，而
   「把座位卡抬高」只是把同一块地方换个方式占掉。带子常驻（不分轮到自己还是轮空），
   所以切换时毡面与手牌零回流。被否的替代：身份与动作共用带里那一行（375px 上内容约 300–360px
   对可用 327px 擦边，一旦换行毡面随回合跳）。
5. **叫牌面板吃满内容槽**，不再写 `top-[22%] max-h-[56%]`；信息面压成一行（`叫牌 · 第 N 副 ·
   40♠（仍 `text-3xl`）· 轮到你`）；内部三处收紧（内边距 16→12、间距各收一档）。
6. **跳叫触发钮独立成行**（档位区下面、右对齐的细钮）：**档位行恒为「数字 + 五格」**，
   槽位补 `shrink-0` 作第二道防线。`BidTrigger` 从 `row-end | full-row | none` 收敛为 `line | none`，
   `row-end` **退休**。
7. **出牌区**：三个点各占**固定宽度预算**（左 `left-0 w-[38%]`、右 `right-[20%] w-[38%]`、
   我 `inset-x-0` 在下），**删掉上下错位**；簇内放不下时由纯函数 `computeClusterStep`
   （`fan-layout.ts`，与手牌扇面同一套宽度口径）按 `--step` 叠起来。38 + 24 + 38 = 100% 这个加法
   就是「三点互不相交」的结构性保证。
8. **计时只换皮**：药丸 + ⏱ + `tabular-nums`，文案 `距上一步 M 分 SS 秒` **一字不改**
   （`ui-check` 的 `clockSeconds` 按它取数并断言真的在走）。仍然不做任何按时间升级的催促色阶。

## 实测（`apps/web/scripts/shot-auction.ts` 的几何断言，360px 与 390px 各一屏）

| 判据 | 改动前 | 改动后 |
| --- | --- | --- |
| 两行档位的同一列**右缘**之差（360px） | **18.27px**（第 5 格宽 36.0 vs 32.3） | **0.00px** |
| 同上（390px） | 0.00px ← 所以这条判据必须跑**窄屏**，否则空转 | 0.00px |
| 叫牌历史容量 | **1 行**（历史区 54.5px） | **8–14 行** |
| 内容槽高度 | 不存在（层各自 `top-*`，与座位卡相交） | **414–494px，三行零相交** |
| 出牌点两两相交 | 靠错位躲（桌面端 5 张起重叠约 26px，6 张约 150px） | **0**（每张牌都在自己那一点的预算里） |
| 托盘 | 在毡面里、无带可住 → 压住「我」卡 | **整个落在动作带内**（毡面之外） |

两条判据是被「量出来」才发现的，源码里看不出来：
- **档位错位**：第 2 档多一枚触发钮 ⇒ 那一行内容超出内宽 ⇒ 而五个槽没有 `shrink-0`，
  flex 只把**这一行**的五格一起压窄 ⇒ 两行的 NT 不再同宽。390px 上放得下（0.00px），
  360px 上是 18.27px —— 真实机型（369px）上是 3.5px，肉眼可见。
- **托盘越界**：带子出现之前，托盘的 y 范围整根落在毡面最后 40px 里。

## 取舍与后果

- **毡面永久少 44px**（那条常驻动作带）。这是决策 4 的代价，换「轮到我 / 轮空」零回流。
- **加/请离机器人要多开一次抽屉**。换卡片矮一整行，且这两个动作本就不是高频动作。
- **机器人身份少一处文字冗余**（徽标行删除），靠头像的 SVG 与名字前缀共同表达。
- **出牌堆积到可读下限以下**（>9 张）时角标会变小 —— 明确的取舍：两簇相撞比一簇略挤更糟
  （相撞时「谁出了什么」直接读不出来）。判据落在 `computeClusterStep` 的单测与
  `minStrip` 的口径上。
- **拟选**（ADR-0021）让「没轮到的在座玩家」也能点牌，所以 `.fan.selectable` 不再等于「该你出手」；
  `ui-check` 相应把「没轮到的人既没有托盘也没有蓝框」改成「没有托盘，但有该跟那一门的蓝框」。
- **看门的两层**：源码守卫（`table-chrome.test.ts` / `bid-panel.test.ts` / `panel-guard.ts`）
  钉形状与枚举；**几何**由 `scripts/shot-auction.ts` 在真浏览器里量并断言（源码看不见几何）。
  按 AGENTS 规则 9 做过三次注入实验：① 把触发钮塞回档位行并去掉 `shrink-0` → 源码守卫与几何守卫
  **同时变红**（实测 10.27px）；② 托盘改回 `bottom-full` → 几何守卫报「托盘 y 632–670 不在带
  y 670–714 里」；③ 把一个状态条塞回毡面最后一行 → **第一次没红**（当时只查我点名的那几个层），
  于是补了「毡面的直接子元素只许是三行与回看浮层」这条穷举判据，再注入即红（越界层 y 657–691
  而内容槽止于 627）。三次都逐字节还原（四个文件的 SHA-256 与注入前一致）。

  （`packages/*` 全部测试不变即证据）。
- **`lobby` 的「点邀请码复制」与「开始第一副」不变**：它们仍住在内容槽里的大厅面板中，
  只是不再需要 `pointer-events-none` —— 那一层不再横跨毡面，所以也不再吃掉别人的点击。
