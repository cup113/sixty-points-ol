# 新手引导用「引导局」取代幻灯片，引导局数据取自真实牌局

`/learn` 从幻灯片式「规则演示」（ADR-0010，含 `/studio` 编排的牌局故事，ADR-0008）改为一门**交互课程**：概念简述 + 门槛式测验 + **引导局** —— 用户坐进一副真实牌局的一个座位，对手两家自动出牌，用户座位的每个动作（叫牌 / 埋底 / 出牌）被引导词**强制**带着打，打完复盘屏全亮三家。三个决定记在这里。

**其一，为什么真实牌局而不是继续编排。** 引导局的教学生命力在「这真是三个真人打出来的」：叫牌的让与争、埋底的取舍、末轮的博弈都带着真实的代价，而不是作者为了讲课摆出来的棋子。取材硬门槛是**三人均非机器人**（`users.is_bot` 全 0 的座位），来源只记桌码/副号/日期，真实用户名不进仓库，页面用固定代称。代价要认：编排局「想要什么课就摆什么局」，真实局只能「有什么课就讲什么课」—— 选副时有就覆盖、没有就降级成纯测验讲透，不硬凑；且每桌只有最后一副完整可还原（老副的手牌不在事件表里），候选池天然有限，不够就现打几副再提取。

**其二，客户端从显式手牌重放，不从种子重放。** 线上牌局用的是每次现取的 `cryptoRng`，本就不可复现；引导数据因此把**事实烘焙**进 JSON（三家 17 张、拿上来的底牌、发牌人、副前级别、完整动作序列），客户端用引擎的 `dealWith` 直接构造那副牌再逐动作 `dispatch` —— 与机器重演（ADR-0016）构造 `ReplayInput` 同一条路。`build-guide` 在仓库里做 `deal:check` 式的核对：每个动作在它那一步必须合法、烘焙事实必须与现场重放逐项一致、用户座位的每个动作必须有引导词。引擎或实现将来变了，已发布的引导局也不会变味。

**其三，全量强制 + 两类拒绝。** 用户座位的动作一个不落全由引导词带打（主流新手教程的「手把手」量级，一副约 20–30 个动作），对手自动出、短延迟可跳过；引导词之外的牌**可点但拒绝**——不合法给引擎的理由（结构优先等，正好是教材），合法但非引导牌指回引导词。测验是**门槛式**：必须答对才能继续、逐项给针对性解释、不记分。引导局的教学桌面与教练栏是独立新组件，复用牌面级组件（HandFan / Card / TrickCluster 等），不碰真桌的四行毡面 chrome —— ADR-0020 / 0021 的桌面守卫原样成立。

退役清单：`/studio`、`lib/story/*`、`docs/deals/*`、故事生成管线与三副已发布故事全部删除（幻灯片没了下游，不养死代码）；ADR-0008、ADR-0010 由本 ADR 取代。深链与进度语义换血：`?s=` 仍是一步一链，但「自动播放」死了，换成 localStorage 的最远步续读。

## 修订（guide-v2）：讲解与测验同屏、导航主 CTA、引导局节奏分档与收墩停留

上面三个核心决定（**真实牌局取材**、**客户端从显式手牌重放**、**全量强制 + 两类拒绝**）一个都没动。
这一节修的是课程的**屏序**与**引导局的手感** —— 起因是七条试用反馈，其中两条最要紧：
「讲解和题目分在不同页，读完翻页才见题，显得断裂」与「对手叫牌/出牌一闪而过、收墩快到看不清」。

### 屏序：一步 = 一屏，讲解与它的测验同屏

- `CourseStep` 去掉独立的 `quiz` 步种，`brief` 步自带 `quiz: readonly QuizGroup[]`。
  组标题保留（「哪些是分牌？」与「数一数：这五张多少分？」是两组，不是一坨题），
  门槛语义不变 —— **全部组答对才放行**；变的是题就在讲解下面，回看不用翻页。
- 课程 id 升 `guide-v2`：localStorage 的续读按 id 匹配，旧进度自然作废一次（教程语境可接受）。
  **被吸收的 quiz 步 id 收进 `GUIDE_ALIASES`**（`course.ts` 导出），于是曾经分享出去的
  `?s=c2-follow-single` 仍落在合并后的那一屏，而不是掉回课程开头。

### 导航：内容底部的主 CTA

- 「下一步」不再只是页脚右下角一枚小钮：内容底部的主 CTA 写**下一节的标题**
  （「下一节 · 主牌由三部分组成 →」），按钮自己预告去哪；被门槛卡住时同一位置写原因
  （「答对才能继续」/「把这一段打完才能继续」），不把这句藏在页脚 10px 小字里。
  翻页时滚回页顶 —— 这是「跳转有明确提示」的视觉半边（`aria-live` 的逐步播报仍在）。
- 页脚删掉「← → 翻步 · 深度链接 ?s=\<step-id\>」与「已读到第 N 步」：前者是**机制**
  （键盘可用、`?s=` 可分享）而不是**说明**，用户不需要读实现；后者是死文案 ——
  没有 `?s=` 时 `onMount` 本就自动续读到上次的位置，它几乎没有机会出现。

### 引导局手感：分档延迟 + 收墩停留 + 叫牌历史

- 对手延迟**分档**：叫牌/埋底 1.5s（要读叫牌历史表与引导词）、出牌 1.1s。旧的统一 700ms
  注释写着「比真桌的机器人（0.5–1.5 秒）快一半」—— 那个前提本身就错：教程该比真桌**慢**，
  不是快，因为读者要同时看牌、看历史、读引导词。
- **收墩停留**：一墩收起时三家牌在出牌区**原地停 2s** 配赢家徽标，才清场进下一轮
  （「跳过等待」可立即过去）。驱动它的是 `stepOnce` / `submit*` 早就返回、却**从未被接线层消费**
  的 `events.trickWon` —— `session.ts` 的注释当时就写着「接线层用它决定要不要等动画」，
  这一版才真的接上（纯函数层因此零改动，符合 ADR-0008 的分层纪律）。
- 叫牌历史复用真桌的 `AuctionHistory`：它的 props 从 `view: PublicView` 收窄成**结构切片**
  （`{ auction, dealerSeat }`），于是真桌（`BidPanel` / `AuctionRecord` 传 `view.deal`）与引导局
  （传引擎 `DealState`）共用同一份三列表格，不写第二份。最高叫品由引擎的 `highestBid` 算 ——
  它同时被收窄为收 `auction` 数列（原先收整个 `DealState`，而它只读 `auction`），
  `view.ts` 里那份私有的 `highestNonPass` 随之删除（同一规则的两份实现合并成一份）。
- 手牌与复盘屏的发牌手牌一律过引擎的 `sortHand`。**这一条是修复既有违约**：CONTEXT.md 的
  「副牌在手牌里的显示序」早就写着「`sortHand` 是单一来源、不许各写一份序」，而引导局把
  **发牌序**直接上了屏（主牌不在前、同色两门相邻），真桌 `personalView` 却是排过的。
- 另修五处：元信息行去掉桌码与「引导目标」（第三份重复，教练栏小标与手牌金虚线已说过）、
  叫牌期对手卡不再冒称「闲家」、对手解说（`deal.notes`，此前几乎永远被「你接下来那手」的
  引导词挤掉）挪进「等对手出手⋯」那条、元信息行加「庄已抓 N 分」
  （引擎 `declarerTrickPoints`，与真桌 **信息须** 同源）、空出牌点不再写「等待出牌」。

### 守卫（本次修订新增/改写）

`test/guide-client.test.ts` 五条源码形状守卫，每条都带**就地反证**（同一个判定跑一遍坏形状
必须判红，于是「守卫不空转」由测试自己永久重证，不靠一次性注入实验）：手牌过 `sortHand`、
节奏分档与收墩停留（`THINK_DELAY_MS` / `PLAY_DELAY_MS` / `TRICK_HOLD_MS` + `trickWon` 同时在，
且单一 `OPPONENT_DELAY_MS` 不许回潮）、叫牌历史挂载、页脚无开发者提示 + 主 CTA 位存在。
`test/guide-course.test.ts` 守住并屏后的结构（`brief.quiz` 组的题面校验、题目 id 唯一）
与**别名表**（每个被吸收的 id 都不再是独立一步、且合并目标真的带测验组）。
`scripts/ui-check.ts` 的 `/learn` 段同步改写：概念屏必须有同屏测验、内容底部必须有主 CTA、
门槛句必须落在 CTA 位、页脚不许出现「深度链接 / 翻步」，且**旧 quiz 步 id 的深链**
必须落到简述屏上（只有题、没有讲解就不再算过）。
