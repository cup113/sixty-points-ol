# 新手引导用「引导局」取代幻灯片，引导局数据取自真实牌局

`/learn` 从幻灯片式「规则演示」（ADR-0010，含 `/studio` 编排的牌局故事，ADR-0008）改为一门**交互课程**：概念简述 + 门槛式测验 + **引导局** —— 用户坐进一副真实牌局的一个座位，对手两家自动出牌，用户座位的每个动作（叫牌 / 埋底 / 出牌）被引导词**强制**带着打，打完复盘屏全亮三家。三个决定记在这里。

**其一，为什么真实牌局而不是继续编排。** 引导局的教学生命力在「这真是三个真人打出来的」：叫牌的让与争、埋底的取舍、末轮的博弈都带着真实的代价，而不是作者为了讲课摆出来的棋子。取材硬门槛是**三人均非机器人**（`users.is_bot` 全 0 的座位），来源只记桌码/副号/日期，真实用户名不进仓库，页面用固定代称。代价要认：编排局「想要什么课就摆什么局」，真实局只能「有什么课就讲什么课」—— 选副时有就覆盖、没有就降级成纯测验讲透，不硬凑；且每桌只有最后一副完整可还原（老副的手牌不在事件表里），候选池天然有限，不够就现打几副再提取。

**其二，客户端从显式手牌重放，不从种子重放。** 线上牌局用的是每次现取的 `cryptoRng`，本就不可复现；引导数据因此把**事实烘焙**进 JSON（三家 17 张、拿上来的底牌、发牌人、副前级别、完整动作序列），客户端用引擎的 `dealWith` 直接构造那副牌再逐动作 `dispatch` —— 与机器重演（ADR-0016）构造 `ReplayInput` 同一条路。`build-guide` 在仓库里做 `deal:check` 式的核对：每个动作在它那一步必须合法、烘焙事实必须与现场重放逐项一致、用户座位的每个动作必须有引导词。引擎或实现将来变了，已发布的引导局也不会变味。

**其三，全量强制 + 两类拒绝。** 用户座位的动作一个不落全由引导词带打（主流新手教程的「手把手」量级，一副约 20–30 个动作），对手自动出、短延迟可跳过；引导词之外的牌**可点但拒绝**——不合法给引擎的理由（结构优先等，正好是教材），合法但非引导牌指回引导词。测验是**门槛式**：必须答对才能继续、逐项给针对性解释、不记分。引导局的教学桌面与教练栏是独立新组件，复用牌面级组件（HandFan / Card / TrickCluster 等），不碰真桌的四行毡面 chrome —— ADR-0020 / 0021 的桌面守卫原样成立。

退役清单：`/studio`、`lib/story/*`、`docs/deals/*`、故事生成管线与三副已发布故事全部删除（幻灯片没了下游，不养死代码）；ADR-0008、ADR-0010 由本 ADR 取代。深链与进度语义换血：`?s=` 仍是一步一链，但「自动播放」死了，换成 localStorage 的最远步续读。
