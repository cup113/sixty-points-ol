# 新手引导用「引导局」取代幻灯片，引导局数据取自真实牌局

`/learn` 从幻灯片式「规则演示」（ADR-0010，含 `/studio` 编排的牌局故事，ADR-0008）改为一门**交互课程**：概念简述 + 门槛式测验 + **引导局** —— 用户坐进一副真实牌局的一个座位，对手两家自动出牌，用户座位的每个动作（叫牌 / 埋底 / 出牌）被引导词**强制**带着打，打完复盘屏全亮三家。三个决定记在这里。

**其一，为什么真实牌局而不是继续编排。** 引导局的教学生命力在「这真是三个真人打出来的」：叫牌的让与争、埋底的取舍、末轮的博弈都带着真实的代价，而不是作者为了讲课摆出来的棋子。取材硬门槛是**三人均非机器人**（`users.is_bot` 全 0 的座位），来源只记桌码/副号/日期，真实用户名不进仓库，页面用固定代称。代价要认：编排局「想要什么课就摆什么局」，真实局只能「有什么课就讲什么课」—— 选副时有就覆盖、没有就降级成纯测验讲透，不硬凑；且每桌只有最后一副完整可还原（老副的手牌不在事件表里），候选池天然有限，不够就现打几副再提取。

**其二，客户端从显式手牌重放，不从种子重放。** 线上牌局用的是每次现取的 `cryptoRng`，本就不可复现；引导数据因此把**事实烘焙**进 JSON（三家 17 张、拿上来的底牌、发牌人、副前级别、完整动作序列），客户端用引擎的 `dealWith` 直接构造那副牌再逐动作 `dispatch` —— 与机器重演（ADR-0016）构造 `ReplayInput` 同一条路。`build-guide` 在仓库里做 `deal:check` 式的核对：每个动作在它那一步必须合法、烘焙事实必须与现场重放逐项一致、用户座位的每个动作必须有引导词。引擎或实现将来变了，已发布的引导局也不会变味。

**其三，全量强制 + 两类拒绝。** 用户座位的动作一个不落全由引导词带打（主流新手教程的「手把手」量级，一副约 20–30 个动作），对手自动出、短延迟可跳过；引导词之外的牌**可点但拒绝**——不合法给引擎的理由（结构优先等，正好是教材），合法但非引导牌指回引导词。测验是**门槛式**：必须答对才能继续、逐项给针对性解释、不记分。引导局的教学桌面与教练栏是独立新组件，复用牌面级组件（HandFan / Card / TrickCluster 等），不碰真桌的四行毡面 chrome —— ADR-0020 / 0021 的桌面守卫原样成立。

退役清单：`/studio`、`lib/story/*`、`docs/deals/*`、故事生成管线与三副已发布故事全部删除（幻灯片没了下游，不养死代码）；ADR-0008、ADR-0010 由本 ADR 取代。深链与进度语义换血：`?s=` 仍是一步一链，但「自动播放」死了，换成 localStorage 的最远步续读。

## 修订（guide-v2）：讲解与测验同屏、导航主 CTA、引导局节奏分档与收墩停留

上面三个核心决定（**真实牌局取材**、**客户端从显式手牌重放**、**全量强制 + 两类拒绝**）一个都没动。
这一节修的是课程的**屏序**与**引导局的手感** —— 起因是七条试用反馈，其中两条最要紧：
「讲解和题目分在不同页，读完翻页才见题，显得断裂」与「对手叫牌/出牌一闪而过、收墩快到看不清」。

### 屏序：一步 = 一屏，讲解与它的测验同屏

- `CourseStep` 去掉独立的 `quiz` 步种，`brief` 步自带 `quiz: readonly QuizGroup[]`。
  组标题保留（「哪些是分牌？」与「数一数：这五张多少分？」是两组，不是一坨题），
  门槛语义不变 —— **全部组答对才放行**；变的是题就在讲解下面，回看不用翻页。
- 课程 id 升 `guide-v2`：localStorage 的续读按 id 匹配，旧进度自然作废一次（教程语境可接受）。
  **被吸收的 quiz 步 id 收进 `GUIDE_ALIASES`**（`course.ts` 导出），于是曾经分享出去的
  `?s=c2-follow-single` 仍落在合并后的那一屏，而不是掉回课程开头。

### 导航：内容底部的主 CTA

- 「下一步」不再只是页脚右下角一枚小钮：内容底部的主 CTA 写**下一节的标题**
  （「下一节 · 主牌由三部分组成 →」），按钮自己预告去哪；被门槛卡住时同一位置写原因
  （「答对才能继续」/「把这一段打完才能继续」），不把这句藏在页脚 10px 小字里。
  翻页时滚回页顶 —— 这是「跳转有明确提示」的视觉半边（`aria-live` 的逐步播报仍在）。
- 页脚删掉「← → 翻步 · 深度链接 ?s=\<step-id\>」与「已读到第 N 步」：前者是**机制**
  （键盘可用、`?s=` 可分享）而不是**说明**，用户不需要读实现；后者是死文案 ——
  没有 `?s=` 时 `onMount` 本就自动续读到上次的位置，它几乎没有机会出现。

### 引导局手感：分档延迟 + 收墩停留 + 叫牌历史

- 对手延迟**分档**：叫牌/埋底 1.5s（要读叫牌历史表与引导词）、出牌 1.1s。旧的统一 700ms
  注释写着「比真桌的机器人（0.5–1.5 秒）快一半」—— 那个前提本身就错：教程该比真桌**慢**，
  不是快，因为读者要同时看牌、看历史、读引导词。
- **收墩停留**：一墩收起时三家牌在出牌区**原地停 2s** 配赢家徽标，才清场进下一轮
  （「跳过等待」可立即过去）。驱动它的是 `stepOnce` / `submit*` 早就返回、却**从未被接线层消费**
  的 `events.trickWon` —— `session.ts` 的注释当时就写着「接线层用它决定要不要等动画」，
  这一版才真的接上（纯函数层因此零改动，符合 ADR-0008 的分层纪律）。
- 叫牌历史复用真桌的 `AuctionHistory`：它的 props 从 `view: PublicView` 收窄成**结构切片**
  （`{ auction, dealerSeat }`），于是真桌（`BidPanel` / `AuctionRecord` 传 `view.deal`）与引导局
  （传引擎 `DealState`）共用同一份三列表格，不写第二份。最高叫品由引擎的 `highestBid` 算 ——
  它同时被收窄为收 `auction` 数列（原先收整个 `DealState`，而它只读 `auction`），
  `view.ts` 里那份私有的 `highestNonPass` 随之删除（同一规则的两份实现合并成一份）。
- 手牌与复盘屏的发牌手牌一律过引擎的 `sortHand`。**这一条是修复既有违约**：CONTEXT.md 的
  「副牌在手牌里的显示序」早就写着「`sortHand` 是单一来源、不许各写一份序」，而引导局把
  **发牌序**直接上了屏（主牌不在前、同色两门相邻），真桌 `personalView` 却是排过的。
- 另修五处：元信息行去掉桌码与「引导目标」（第三份重复，教练栏小标与手牌金虚线已说过）、
  叫牌期对手卡不再冒称「闲家」、对手解说（`deal.notes`，此前几乎永远被「你接下来那手」的
  引导词挤掉）挪进「等对手出手⋯」那条、元信息行加「庄已抓 N 分」
  （引擎 `declarerTrickPoints`，与真桌 **信息须** 同源）、空出牌点不再写「等待出牌」。

### 守卫（本次修订新增/改写）

`test/guide-client.test.ts` 五条源码形状守卫，每条都带**就地反证**（同一个判定跑一遍坏形状
必须判红，于是「守卫不空转」由测试自己永久重证，不靠一次性注入实验）：手牌过 `sortHand`、
节奏分档与收墩停留（`THINK_DELAY_MS` / `PLAY_DELAY_MS` / `TRICK_HOLD_MS` + `trickWon` 同时在，
且单一 `OPPONENT_DELAY_MS` 不许回潮）、叫牌历史挂载、页脚无开发者提示 + 主 CTA 位存在。
`test/guide-course.test.ts` 守住并屏后的结构（`brief.quiz` 组的题面校验、题目 id 唯一）
与**别名表**（每个被吸收的 id 都不再是独立一步、且合并目标真的带测验组）。
`scripts/ui-check.ts` 的 `/learn` 段同步改写：概念屏必须有同屏测验、内容底部必须有主 CTA、
门槛句必须落在 CTA 位、页脚不许出现「深度链接 / 翻步」，且**旧 quiz 步 id 的深链**
必须落到简述屏上（只有题、没有讲解就不再算过）。

## 修订（guide-v3）：课程重塑成一出五幕剧 —— 概念跟着牌走，门一口气过完

上一节的核心决定（真实牌局取材、显式手牌重放、全量强制 + 两类拒绝）与引导局手感（分档延迟、
收墩停留、叫牌历史、sortHand）**全部原样保留**。这一节动的是课程本身的结构与口吻 ——
起因是一次完整的审美重估：guide-v2 的课程是一门「带牌桌的教材」，不是「带教材的牌桌」。

### 病灶

- **理论先行**：开局连读两章「基础概念」（约 10 屏纯文字）才摸到第一张牌；主牌的座次在
  你见过任何一局叫牌**之前**就讲完了 —— 概念出现在它有意义之前。
- **测验是考试**：约 50 道门槛题、多屏挂 4–6 题的判断墙（「回合的顺序」一组 6 题）。
  一门新手引导让学员在摸牌前先通过 6 连判，是资格考试的形状。
- **教材口吻**：标题带编号（「6.1 阻击叫」）、章节名是分类（「基础概念 I/II/III」）、
  正文是规则书腔 —— 没有叙事、没有「你」，读起来像文档而不像有人带你上桌。
- **旅程不可见**：进度是一条 0.5px 细条加「N / 26」计数，章是一个下拉框 —— 电子表格，
  不是「你走到哪儿了」。

### 药方：五幕剧

- **幕即旅程**：上桌 → 坐庄 → 底细 → 直觉 → 毕业。幕名是路标不是分类名；页头写
  「第 N 幕 · <幕名>」，页头按钮摊开**课程地图**（五幕全程、状态点走过/在看/没到、
  每步带「读 / 读·试 / 打 / 盘」小记号）。「N / 26」计数删了 —— 进度条 + 幕次 + 地图已说全。
- **概念跟着牌走**：首副**三屏内开打**（纯概念屏至多两屏：抢什么 → 怎么叫 → 发牌）；
  主牌的座次挪到第一副叫牌成交**之后**（那门主牌你刚亲眼见它被叫出来）；结算的账挪到你
  亲手埋过底之后。第三幕「底细」集中放**需要一副经验才讲得动**的规则（赢墩两条路、
  结构优先、顺子细则、无主、算账），第四幕「直觉」收拢老手判断。
- **门一口气过完**：一屏**至多一组**、每组**至多四题**，全课程 11 组约 19 题（原 16 组约 50 题）。
  门槛语义不变（答对才放行），被砍掉的题要么折进保留题的选项解释里、要么折进正文 ——
  纠偏教材还在，考试形状没了。组标题一律「试一下：…」。
- **教练口吻**：短句、对「你」说话、标题是钩子（「整副牌里只有 100 分」「主牌：一支排好座次的
  队伍」）；门槛句从「答对才能继续」的判官脸换成「不急 —— 把上面的小题答对，就翻下一页」。
- **过门有回应**：测验全对那一刻 CTA 自动滚进视野（下一步在哪不用找）；引导局打完先亮
  「✓ 这一段打完了」再给按钮；结尾屏改成**毕业屏** —— 四副真牌的成绩单 + 回大厅开桌。
- **换血成本照旧只付一次**：课程 id 升 `guide-v3`，localStorage 续读作废一次（先例 guide-v2）；
  `GUIDE_ALIASES` 从「v2 quiz 步的登记簿」升格为**两代退役 id 的完整账本**（32 个 v2 步 id +
  16 个 v2 quiz 步 id），`guide-course.test.ts` 拿这份清单核完整性 —— 漏登记一个就是红。

### 不变的

引导局数据（四副、slug、段拆分闲家→庄家→庄家→闲家不变）、门槛语义（答对/打完才放行）、
主 CTA 的形状（「下一节 · <标题> →」）、`?s=`/键盘是机制不是说明、以及 guide-v2 的全部手感。

## 修订（guide-v3 桌面手感）：座位气泡、两行式收墩、叫牌金框的轮次门

课程结构（五幕剧）与引导局数据不动。这一节修的是教学桌面在**叫牌与打牌阶段**的三条手感反馈：

### 病灶

- **解说挤成一坨**：一轮里三家的解说轮流挤进「等对手出手⋯」那一条，谁说的全靠
  「代称：」前缀辨认；座位、牌、话三者的位置关系在屏幕上对不上。
- **金框抢跑**：叫牌盘的引导金格（含「不叫」金钮）由「你**接下来**那一手」驱动 ——
  对手还在叫、还没轮到你，金框就亮了，学员以为该自己叫。
- **收墩跳变**：出牌区三列按**出牌顺序**落位（同一家的牌每轮换列），收墩停留结束后
  整墩**消失**、又在底下以另一种排版（「上轮 · X」横排）**重生** —— 传送门式跳变；
  上一墩还只在「新一墩还没人出牌」的空档里可见，一开打就没影了。

### 药方

- **座位气泡**：座位行**三家齐**（含「你」），列序与出牌区一一对齐；对手动作的
  `notes` 解说挂在**动作者那一席**正下方的气泡里（巷高按三行预留，冒泡不顶动桌面，
  `{#key}` 换一条重弹一次）。教练栏从此**只对你的手说话** —— 气泡说对手，分工写进
  CONTEXT.md「教练栏 / 座位气泡」两条。
- **两行式出牌区**：效仿正式打牌摆两行 —— 第一行永远是「这一墩」（谁出的牌摆在谁那一列，
  列序 = 座位序，不再随出牌顺序换位），第二行是「上一墩」缩一档常驻（`.trick-mini` 把
  `--cw` 收到 34px，与 `.hand-strip` 同一条缩档手法）。收墩不清场：整墩带着**同一个 key**
  （墩序）从第一行 `animate:flip` 搬进第二行（Svelte 的 flip 量两端尺寸差，位移与缩放
  一起补间），被更老的一墩顶出去时才退场。赢家徽标摆在赢家那一列 —— 与真桌 `TrickArea`
  同一语义：位置即身份，于是牌堆连名字 caption 都省了。
- **轮次只有一个真相源**：`actingSeat` = 段内下一条动作的座位。座位卡的轮次金环、
  叫牌盘的 `active` 门（引导金格与「不叫」金钮只在真轮到你时亮，盘头同步亮「轮到你了」）、
  等待栏的「X 在想⋯」读的都是它 —— 金框与轮环同一瞬间亮，抢跑在结构上不可能。
  引导预读不丢：轮到你之前教练栏照旧给「接下来那一手（先读着）」。
- **reduced-motion**：flip/fade 是 Svelte 过渡不是纯 CSS，`GuideBoard` 按
  `matchMedia('(prefers-reduced-motion: reduce)')` 把时长归零 —— app.css 那条
  「Svelte 过渡由组件自己归零」的注释从此有了兑现者。

### 不变的

四副引导局数据与动作序列、全量强制与两类拒绝、分档延迟（1.5s/1.1s）与 2s 收墩停留、
`sortHand` 与三列叫牌历史表、快照 `$state.raw` 纪律。守卫新增三条源码形状（座位气泡 /
两行式 flip / 金框 active 门，各带就地反证），ui-check 的引导局探针补座位行三家齐与
两行区钩子。

## 修订二（guide-v3.2 手感第二轮）：粗体渲染、双气泡并存、教练栏上移、桌面信息须

课程结构与引导局数据不动，修的是试玩回来的四条手感反馈。

### 病灶

- **星号上屏**：气泡/教练栏/复盘屏把数据里的 `**粗体**` 原样端出来（BriefCard 之外
  的文案面都没解析，读者看到两个星号而不是重音）。
- **一冒就走**：气泡只挂「最近一条」解说 —— 小满刚说完、阿凯一开口，小满的话就没了，
  两条对话从不同屏，像打字机不像牌桌。
- **建议垫底**：教练栏排在手牌、托盘之后的最底下 —— 它是引导局唯一的讲解面，
  学员读完牌还要往下找一圈才知道该出哪几张。
- **实时数太不显眼**：级牌、庄已抓、轮数、定约缩在出牌区顶上一行 10px 灰字里 ——
  真桌把它们摆成信息须的大号金字，引导局反而教人「别看这几个数」。

### 药方

- **`RichText`（唯一一份最小解析）**：按 `**` 切段、奇数段 `<b>`，不引 markdown 依赖；
  BriefCard 原先那份内联解析收编进来，概念简述/座位气泡/教练栏/复盘屏四个面共用。
  ui-check 另加「渲染出的 HTML 不含 `**`」的页面级反证（概念屏首屏就带粗体，SSR 可断言）。
- **`SAY_WINDOW = 2`**：气泡巷同时留最近两条对手解说，新的一条 fade 冒出、旧的留在原席
  （`{#key 动作下标}` 换条重弹）；同一席连说两条（赢墩又领出）只留最新，那一席原地换字。
- **教练栏上移 + 加重**：排到手牌**正上方**（`data-guide-hand` 锚点钉住顺序，形状守卫
  「`<CoachBar` 必须在它之前」带反证）；底色/描边加重一档、正文 13px —— 教学桌面里
  它是最该被一眼看到的东西之一。
- **桌面信息须（引导局版）**：定约 / 级牌 / 庄已抓 / 轮数四格金字表住进出牌区顶上
  （真桌 `InfoRail` 同一套视觉语言：标签小、值大、`tabular-nums`）；叫牌没结束时
  「定约」格先摆当前最高叫品（它就是要成为定约的那个）。底部元信息瘦成「身份 · 副号」，
  实时数不在两处抄。

### 不变的

引导局数据、动作序列、段拆分、全量强制、分档延迟与收墩停留、两行式出牌区、`actingSeat`
轮次真相源。守卫新增四条源码形状（RichText / SAY_WINDOW / 教练栏在手牌上方 / 信息须，
各带就地反证），ui-check 引导局探针补信息须四格、教练栏-手牌顺序与「无星号」断言。

## 修订三（guide-v3.3 字数大瘦身）：电报式文案、字号抬一档、动效替字

课程结构、引导局数据、门槛语义不动。这一节起因是一轮「读起来太累」的自查：
讲解与界面的字太多、太小，而多数字在重复桌面已经可视的东西。

### 病灶

- **解说太长**：座位解说/教练词动辄两三行，读者要读完一段才敢点牌 —— 而那一段说的
  就是眼前这张牌。
- **字太小**：教学屏正文 10–12px 居多（比真桌还小），最该一眼看清的面反而最费眼。
- **第三份提示**：叫牌确认提示行、埋底蓝框提示行、底部元信息行（身份 · 副号）——
  金框、蓝框、页头幕次已经在说同一件事，字成了复读机。

### 药方

- **文案电报化**：`docs/guide/*.json` 共 112 处替换（教练词 ≤30 字、座位解说 ≤16 字、
  复盘逐墩 ≤20 字），`course.ts` 讲解要点压成一行一句（50 处）；`**粗体**` 只留给关键概念，
  戏眼（抠底、级牌揭晓）保留。
- **字号抬一档**：教练词与简述要点 15px、题面 16px、信息须数值 18px 黑体、按钮 14px
  加大命中区；10px 只留给课程地图的小记号。
- **动效替字**：信息须数值一变 `pts-pop` 弹一下（每格 `{#key}`）；教练栏目标指示与
  叫牌盘「不叫」在轮到你时呼吸金光（`coach-glow`，reduced-motion 清单归零）——
  「值变了」「该你了」这些话不再用字说。
- **删第三份提示**：底部元信息行、叫牌确认提示、埋底蓝框提示、复盘底牌的保底/抠底
  算账括号全删；待接数据的 pending 块收成一行；毕业屏成绩单压成两短句。

### 不变的

四副引导局的数据字段与动作序列（只动了其中的文案）、全量强制与两类拒绝、分档延迟与
收墩停留、两行式出牌区、`actingSeat` 轮次真相源、RichText 无星号、门槛句与深链锚点
（ui-check 钉住的片段原样保留）。守卫未新增 —— 本轮全是文案与样式，既有守卫
（反星号、信息须四格、教练栏-手牌顺序）继续看住不变的部分。
