# 0023 · Gitee 登录：令牌永不离开服务器

状态：已接受

## 背景

ADR-0003 把「可复制的凭据串」立成**明确的产品需求**：`base64url(名字:令牌)` 复制粘贴即可跨设备
迁移身份，无密码、无找回。取消这条不现实（它是这个项目唯一的迁移手段）。

现在要加一个 **Gitee 登录**选项，并且要求：**Gitee 登录者不得复制凭据**。

这条要求不能靠「界面不显示复制按钮」满足 —— 看一眼当时的实现就知道：

- 凭据串**本身就是会话**：`setCredentialCookie` 把 `base64url(名字:令牌)` 原样写进
  httpOnly cookie `sixty_cred`。httpOnly 只挡 JS，**挡不住用户打开 devtools 看 cookie**；
- 于是「藏起按钮」只是把复制动作从一键变成三步，而**权限一点没少**。

而这条要求最要紧的落点正是**管理员**（ADR-0024）：管理员是权限最高、最不可能接受
「一串可复制的字符串就等于我」的身份。所以「不得复制」必须是**结构性**的，不是 UI 约定。

## 决策

1. **Gitee 身份是另一种身份来历**：`users.gitee_id`（唯一，部分索引排除 NULL）为键；
   首次登录自动建身份，站内名从 gitee `login` 派生（截断到 12 字，撞名加 `-2`…后缀）。
   **绝不合并进同名的本地身份** —— 那会重新打开「输入别人的名字等于接管他」的口子（ADR-0009）。
2. **令牌永不外发**：Gitee 身份的 `users.token` 照旧随机生成，但**不签发凭据串**、
   不出现在任何 JSON 响应里、不进 localStorage。它只有「列非空」这一个用途。
3. **浏览器持有的是会话**：`sessions` 表里的不透明随机 token，装在 httpOnly cookie
   `sixty_session`（30 天滚动）。它与凭据串的差别有两处，都是有意买的：
   **可撤销**（登出即删行，连被复制走的 cookie 值一起失效）、**不可迁移**（换设备再登一次）。
4. **凭据 cookie 与会话 cookie 在写入点互斥**：Gitee 回调设会话时清凭据 cookie，
   `claim` 导入本地身份时清会话 cookie —— 一个浏览器同一时刻只有一个身份。
5. **Gitee 登录只在登出态可用**：已有身份时 start 路由 302 回大厅。
   于是「在座时换 Gitee 身份」这条**幽灵占位**路径根本不存在（本地身份换身份仍受
   ADR-0009 的「先离座再换身份」约束）。
6. **改名不重签发凭据**（只限 Gitee 身份）：会话 cookie 与名字无关，改名只改库。
   本地身份维持原样（名字内嵌在串里 → 改名必重签，否则旧串当场失效）。
7. **不进 MCP**：`/api/mcp` 只认凭据串（`identityFromCredentialOnly`，凭据 cookie + Bearer，
   不看会话 cookie）。Gitee 身份拿不到凭据串，也就进不了 **MCP 工具面**；
   想用 MCP 就另建一个本地身份（README 本来就把 MCP 客户端当「另一台设备」）。
   带会话 cookie 的浏览器请求撞 `/api/mcp` 按**无身份会话**处理 —— 会话不该长成第二根 MCP 凭据。
8. **state 用 HMAC**：签名内容含时间戳、随机 nonce 与邀请码 `join`，10 分钟有效；
   密钥取 `SIXTY_GITEE_STATE_SECRET`，未设时从 client secret 派生（少一个必配项；
   轮换 client secret 只作废 10 分钟内的在途授权）。选 HMAC 而不是「随机串存 cookie」，
   是因为部署侧本来就要去 Gitee 开放平台建应用、填回调，多一个密钥不是负担。
9. **未配置即隐身**：`SIXTY_GITEE_CLIENT_ID` / `_SECRET` 任一为空 → 按钮不渲染、
   `start` 与 `callback` 一律 404。功能开关就是配置本身，没有第二个布尔量。

## 后果

- **Gitee 身份不能驱动 MCP。** 这是有意买的边界，不是遗漏；不想要这条就得给 Gitee 另签一根
  可复制的专用令牌，而那正好推翻决策 2。
- 会话被盗的窗口是 30 天（滚动）—— 但**可撤销**，而凭据串不可撤销：这是 Gitee 身份比本地身份
  更「轻」的地方。管理员因此挂在 Gitee 侧（ADR-0024）。
- 本地身份的一切行为**一字未变**：凭据串照发、改名照重签、旧串照失效、MCP 照用、
  `spectate-check` 与既有单测全部不受影响。
- 凭据串与会话从此是**两种东西**（见 CONTEXT.md 的 **会话** 条目）：一个可复制、不可撤销、
  跨设备；一个不可复制、可撤销、绑定登录来源。

## 守卫

- **双向非泄漏**（`test/auth-gitee.test.ts`，按 AGENTS 规则 9 证明守卫非空转）：
  Gitee 身份经改名路由与大厅 load **都拿不到** `credential` 字段、响应里不含令牌本体；
  同一条路对本地身份**必须**给出凭据串。少了后半句，这条守卫可能只是「字段名写错」的产物。
- **同名不合并**：Gitee 派生名撞上既有本地身份时加后缀，绝不顶掉那条身份（单测）。
- **Gitee 身份卡上没有「复制凭据」**：`pnpm shot:gitee` 在截 Gitee 身份那一屏时断言
  `mustNotContain: ['复制凭据']`，并断言小图标入口存在。
- **会话**：过期即查不到且行被回收、机器人不可有会话、登出撤销后立刻失效、滚动续期（单测）。
