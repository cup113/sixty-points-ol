# 委托不叫：叫牌阶段的「这一副剩下的都不叫」，由浏览器慢半拍出手

叫牌只有轮到你时才出现「不叫」，而「我不打算叫」这件事**在轮到你之前就已经知道了**。
牌桌上最常见的一种卡顿由此而来：一个人心里已经决定不叫，却还得盯着等别人叫完、等轮次亮起来
再点一下；要是他正好走开，整桌就一直等（引擎没有超时 —— 「距上一步」那枚闹钟只报时，不出手）。

这一条给在座玩家一句话的权利：**这一副凡是轮到我，都替我按「不叫」**。说完就能撒手。

## 决策

1. **它是本机偏好，不是服务器状态**。委托存在 `localStorage`（`sixty.auto-pass.<邀请码>`，
   值是**副号**），与音量 / 震动同一类：不进负载、不进数据库、不跨设备。于是没有台账、没有新端点、
   没有服务端重算器，`packages/*` 一字不动。
2. **由浏览器出手，而且慢半拍**。轮到我时页面等 `500~1500ms` 随机再发出一次 `bid 'pass'`。
   这个区间与机器人的出厂延迟（`SIXTY_BOT_DELAY_MIN_MS` / `_MAX`，ADR-0015）是同一档 ——
   桌面读不出这是代按，也不必读：它就是我的一次 pass。
3. **一拍一副一次**。记账键是 `副号:叫牌史长度`（`apps/web/src/lib/auto-pass.ts` 的 `beatKey`）：
   同一拍重复到达、重连补帧都不会发第二次；而同一副里第二次轮到我时是**另一拍**，照旧代按。
   记账先写、**发失败再退回来** —— 一次网络抖动不该让这一拍永远没人按；
   而退回来之后**按 500 / 1000 / 2000 / 4000ms 退避重试、整拍最多 5 次**
   （`autoPass.ts` 的 `autoPassRetryDelay` / `AUTO_PASS_TRIES`，理由见下方「取舍」）。
4. **只覆盖叫牌**。埋底与出牌永远是人的决定，代劳那两处就是托管，`CONTEXT.md` 明确避开。
   管道也只有一条：代按与手按走同一个 `applyTableAction`，引擎、事件流、`validateCall` 一字不改。
5. **界面只有一处入口**：叫牌面板页脚的一行复选「这一副剩下的都不叫」，**排在「不叫」主按钮之后**、
   同列低一级（读作那个按钮的延伸）。委托后同一行变金色、方框实心 + 墨色勾。
   别人的座位卡上不加任何标记 —— 代按是瞬时的，没有人会因为这条委托多等一秒。
6. **委托时不响「该你了」**（`SoundSnapshot.autoPass`）：那一句是提醒你去看一眼，而你已经把这一副
   交出去了；否则它会先催你一下、紧接着又被一次自动的 pass 按掉。
7. **叫牌一结束就清账**（`auto-pass.ts` 的 `armedAfter`）：每帧只允许保留「**正在叫牌的那一副**」的
   副号，其余一律清掉。于是台账里永远只可能躺着一个当下有效的委托 —— 刷新、断电、关机都不影响
   （重新打开时那一副若还在叫牌，委托照旧在）。它还顺手治掉一个只有「存副号」才会有的窟窿：
   `开新对局` 会把副号从 1 重新数起，若第 1 副勾过委托之后就没再动过，那条 `1` 会在新对局的
   第 1 副重新生效 —— 等于「我明明没委托，却被自动 pass 了一整副」。

## 取舍与后果

- **关掉页面就不作数**。它是尽力而不是保证：页面关掉、被冻结、断网时代按不会发生，桌面照旧等。
  这一版承诺的是「顺手」（我在看、但不想点），不是「兜底」（我不在也别让桌面停住）。
  兜底需要服务端在牌局里替人出手，还要给规则加一条「期限」——那是另一件事，不做。
- **它会点亮在线点、吃掉「暂离」气泡**。代按成功那一刻，这次出手**确实是这一页发出的**：
  `applyTableAction` 照旧记「最近活跃」、删掉 `away` 消息。不做掩盖 —— 想「挂着暂离又让桌面继续走」
  的人要的是兜底，不是这一条。
- **两个标签页都开着**时两边各排一拍、各发一次：先到的生效，晚到的被引擎拒「还没轮到你」。
  所以代按走 `bid('pass', { quiet: true })` —— 失败不写页头横幅（那不是用户刚点的动作），
  而帧一到、记账一对，另一侧的定时器随即撤掉。
- **失败的重试有退避、有预算**（这一条是补写的：原先只写了「发失败就退回来」，没写退到哪里为止）。
  代按失败之后**不会再来下一帧**（SSE 已断、或服务端不可达），而这一拍之后可能再也没有别人出手 ——
  「失败就立刻再排一拍」于是成了一条**每秒重发一次**的循环：每轮把 `busy` 翻一次（手动「不叫」、
  托盘、页头那几枚按钮跟着灰一下），页头刚写上的横幅也被每秒抹一次。退避把「网络抖一下」
  （一两拍就成）与「网真断了」（很快把预算烧完并停下）分开。**预算用完不等于放弃委托**：
  记账键照旧清着，下一次负载（重连补帧）会把预算归零、重新开始 —— 桌面不会卡在一个谁也不按的轮次上；
  同时写一句页头提示，让人知道这一拍得自己按。
  与此配套，`quiet` 的请求**既不置 `busy` 也不碰 `error`**：那两个状态位属于「用户刚点的动作」。
- **换设备 / 清站点数据后要重勾**。与音量为同一条纪律；跨设备同步一条「我这一副不叫」没有意义。
- **`panel-guard.ts` 的定位判据跟着改了**：页脚文案里也有「不叫」二字，早先那条「在文本里找这两个字、
  再往前找最近的 `<button`」会把页脚当成主按钮（它没有 44px 命中区，于是对正确的源码报假红，
  而且只在「没轮到我、主按钮没渲染」的页面上出现）。现在先认 `data-pass-button` 钩子，
  再退回「整段文字恰好是『不叫』」——认「这个元素说的是什么」比认「这两个字在前面还是后面」硬。
- **不做「超过 45 分我就不叫」的限价**：那是在替我**叫**，等于托管的半边。

## 与旧 ADR 的关系

- **不再需要 ADR-0002 之外的新权威源**：委托只是「谁在什么时候按了那个按钮」的提前量，
  服务端仍然只认 `applyTableAction`。
- **与 ADR-0021（拟选）同族**：都是浏览器侧的意图状态，都不越过「出手只由托盘/服务端那一句决定」。
  区别是拟选**不排任何动作**，而这条排了一个 —— 所以它必须自己守住「一拍一次」「随副次作废」。
- **收窄 ADR-0020 的面板页脚**：页脚从此是「主按钮 + 一行复选」两块，都 `shrink-0`、都在正常文档流里，
  面板里仍然只有叫牌历史那一个滚动区。
- **不动 ADR-0015**：机器人照旧由服务端调度；本条的延迟区间只是**借用**它的出厂值，让两者节奏一致。
