# 拟选：没轮到你也能点牌，而牌局推进不再刷掉选择

出牌是**需要提前想**的事：要出哪几张、跟不跟得起、留不留分。而在此之前，手牌只在
「这一手归你动」时可点（`selectable = 出牌阶段 && playTurn === 我的座位`，或埋底轮到庄家），
轮到别人时整手牌是**冻结**的 —— 最自然的动作（先点两张摆着看）被无声忽略，临到出手那一刻才开始点，
是现实里最常见的情形。这一条把「在手牌上随时可以点牌」变成常态。

## 决策

1. **在座玩家的手牌随时可点**（`+page.svelte`）：`selectable = myTurnPlay || planning`，
   `planning = 在座 && 出牌阶段 && 本墩已有领出`。本轮之内**不新增任何界面元素** ——
   不加「拟选 N 张」的操作条，也不做提前校验（那会在选到一半时就开始报错）。
2. **牌局推进不再清空选择**（`selection.ts`）：清空判据从「`view.version` 变了就清」改成
   **「角色 / 我的座位 / 我的手牌变了才清」**（手牌按 `cardKey` 序列做指纹）。
   - 别人出牌、收墩、换轮次：**不清**（这正是拟选能活过一帧的前提）；
   - 换副、全 pass 重发、补位接下别人的牌、我刚出手：**清**（那些牌已经不在手上）；
   - 名单与在线点变化：**照旧不清**（早先那条判据的由来 —— 服务端在任何人连上/断开时都会广播
     一帧，无条件清空等于让观战者的连断刷掉在座玩家正在选的牌）。
3. **跟牌蓝框跟着放宽到同一个条件**（`markedKeys`）：`planning` 为真时，给在座玩家标出
   **领出那一门**的全部手牌。「该跟哪一门」正是要提前看的事，而它与 `planning` 的判据天然同源
   （都是「本墩已有领出」）；领出者那一张还没落地时谁也标不出来，集合自然为空。
4. **合法性仍然只由托盘判**：轮到你时 `playError` 调引擎的 `checkPlay` 说明这组牌为什么不行
   （既有实现，一字未改）。拟选**不做**提前校验 —— 那是「一边选一边报错」，与「先摆着看」的意图相反。
5. **观战者永远没有拟选**（没有手牌、没有 `you`），分支沿用既有写法。

## 取舍与后果

- **跨墩保留的代价**：你在上一轮拟的牌，下一轮可能已经跟不上了。**不移除**它 ——
  轮到你时托盘会给出不合法原因，蓝框也会跟着新的领出重新标出该跟哪一门，两者一起说清「选错了」。
  另一个选择（每次局面推进就清）会让拟选活不过一次别人出手，等于没做。
- **`.fan.selectable` 的语义变了**：它不再等于「该你出手」，而是「你可以点」。`ui-check` 相应把
  「没轮到的人既没有托盘也没有蓝框」改成「**没有托盘，但有该跟那一门的蓝框**，且手牌是可点的」，
  蓝框数量仍从 `/view` 现算（不写死花色）。
- **`SelectionContext` 去掉了 `view`**：既然判据不再看版本，就没有理由留着它 ——
  结构上做不到「因为版本变了而清空」，比靠注释提醒更可靠。
- **看门的三层**：`selection.test.ts` 的四条判据（首帧清 / 无关帧不清 / 推进不清 / 手牌变了清）
  + `table-chrome.test.ts` 的源码守卫 + `ui-check` 在真页面上的断言。

## 与旧 ADR 的关系

- **收窄 ADR-0020 的一处后果**：那条把「没轮到的人」的界面后果写成「没有托盘也没有蓝框」，
  本条把蓝框那一半放宽（托盘仍只在该你出手时出现）。
- **不动引擎与服务器**：拟选自始至终是浏览器侧的选择状态；出手仍是 `client.play()` 那条
  服务器权威路径，非法组合照旧被服务端拒（引擎的 `checkPlay` 是唯一判据）。
